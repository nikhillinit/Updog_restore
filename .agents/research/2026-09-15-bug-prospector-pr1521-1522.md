## Detailed Findings

### 1. `portfolio-company-summary.tsx:93-110` (fac5fca18) - "Unavailable" shown while loading; fail-closed flag ignored

**Lens:** Error Path Exerciser, State Machine **Assumption:** the overview
response is either present or genuinely unavailable. **Violation scenario:**
every page load: `company` resolves before `portfolioOverview`, so the three
cards claim "Unavailable" for a value that is merely in flight. A settled
overview with `provenance.isFinanciallyActionable === false` was also rendered
as numbers although `usePortfolioOverview` reports it unavailable.
**Consequence:** wrong UI (a truthfulness label that is false for the pending
window). **Fix:** `1d37b175e` (from PR #1523) renders "Loading..." while pending
and treats `isUnavailable` as no metrics; unit coverage added for both states.

### 2. `portfolio-company-summary.tsx:51-54` (fac5fca18) - recorded zero ownership rendered as missing

**Lens:** Boundary Conditions (zero) **Assumption:** ownership is either
positive or unknown. **Violation scenario:** a company whose ownership was
recorded as `0.0000` (the internal corpus has both null and zero rows).
**Consequence:** wrong UI; a recorded fact displayed as "Not captured". **Fix:**
`2aad60e9f` (from PR #1523): only null, blank or non-numeric input falls back;
zero renders as `0.00%`.

### 3. `useLiquidityAnalytics.ts:123-180` - demo forecast emptied by the new status filter

**Lens:** State Machine Analysis, Data Lifecycle Tracing **Assumption:**
`getTransactions()` contains upcoming rows when the forecast runs. **Violation
scenario:** demo mode (`allowDemoFallback: true`): the generator dated all 50
mock rows in the past year with `status: 'executed'`, and
`generateLiquidityForecast` (changed in #1521) keeps only
`planned / pending / approved`. **Consequence:** `plannedCapitalCalls`,
`expectedDistributions` and `plannedInvestments` are 0 in the demo forecast;
only the hardcoded fee and mock recurring expenses remain. **Fix:** `1970b2bbc`:
26 weeks of executed history plus 26 weeks of planned rows; `executedDate` only
on executed rows; test asserts the demo forecast keeps planned flows.

### 4. `help.tsx:113` - stale Scenarios guidance

**Lens:** Assumption Audit (documentation vs shipped product) **Fix:**
`dfdcd614b`: FAQ now points at Fund Model Results > Scenarios (Scenario
Workspace) and states that company detail is summary-only.

## Fragile Code (Works Now, May Break Later)

### F1. `shared/core/liquidity/LiquidityEngine.ts:635-639` - management fee hardcoded at 2%

**Lens:** Assumption Audit **Current behavior:** `projectManagementFees` returns
`fundSize * 0.02 / 12 * months` and ignores the `management_fee` transactions
that `fund-cashflow-inputs.ts` now emits at the fund's real rate. **Breaking
scenario:** any fund whose `managementFee` is not 0.02. Prod fund 2 is 2%, so
today the numbers agree by coincidence. **Recommendation:** give
`LiquidityEngine` a fee-rate option (default 0.02) and pass `fund.managementFee`
from the hook, or sum provided fee rows when present. Left unchanged here
because the engine's projection is sum-of-inputs by contract and the server
route `/api/liquidity/forecast` shares it.

### F2. `client/src/hooks/useFundCashFlowInputs.ts:26-31` - query failure collapses into the empty state

**Lens:** Error Path Exerciser **Current behavior:** a failed
`GET /api/investments?fundId=` leaves `investments` undefined, the hook returns
undefined, and the Cashflow tab renders the same explicit empty state it shows
for a fund with no data. No retry affordance, nothing logged to the user.
**Recommendation:** return `isError` alongside the inputs and let
`CashflowDashboard` render its unavailable state with a retry.

### F3. `client/src/hooks/useLiquidityAnalytics.ts:465-514` - monitoring interval churn (pre-existing)

**Lens:** State Machine Analysis **Current behavior:** `startRealTimeMonitoring`
depends on the whole `options` object, which is a new object on every render
(the dashboard spreads `...fundInputs`), so the effect tears the interval down
and recreates it on every re-render; the 30 s refresh timer restarts each time.
**Recommendation:** depend on `options.autoRefresh` and
`options.refreshIntervalMs` rather than `options`.

### F4. `client/src/lib/cashflow/fund-cashflow-inputs.ts:105-108` - fund start fallback

**Lens:** Time-Dependent Bugs, Assumption Audit **Current behavior:**
`fundStart = establishmentDate ?? Date.UTC(vintageYear, 0, 1)`. Prod fund 2 has
a NULL `establishmentDate`, so fees accrue from 2024-01 although the first
investment is 2024-07 (documented in the PR). If both fields were null,
`Date.UTC(undefined, 0, 1)` is NaN and every month index becomes NaN.
**Recommendation:** treat a missing vintage as "no fee history" rather than
propagating NaN; populate `establishmentDate` for fund 2.

### F5. `client/src/hooks/useFundCashFlowInputs.ts:27` - private query key

**Lens:** Data Lifecycle Tracing **Current behavior:** the investments read uses
`['fund-cashflow-investments', id]`, distinct from `companyInvestmentsQueryKey`,
so investment mutations elsewhere never invalidate it; the tab can lag a new
investment by up to the 60 s `staleTime` plus a refocus. **Recommendation:**
share one investments query key with `useCompanyInvestments`.

### F6. `client/src/lib/cashflow/fund-cashflow-inputs.ts:123-129` - unparseable investment dates

**Lens:** Boundary Conditions **Current behavior:** an invalid `investmentDate`
yields NaN indexes; the row is classified `planned` with an invalid date and the
sort comparator returns NaN. The column is a database date, so this is Rare.

### F7. `client/src/lib/cashflow/fund-cashflow-inputs.ts:98-100` - as-of captured once

**Lens:** Time-Dependent Bugs **Current behavior:** `asOf = new Date()` is
evaluated inside the builder memo; a tab left open across a month boundary keeps
the stale as-of until an input changes.
