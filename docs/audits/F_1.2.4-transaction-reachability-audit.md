## Neon-lane spike outcome (plan §5 prerequisite)

**Verdict: local neon-proxy container is FAITHFUL — the container lane is
viable; no Neon branch-DB fallback needed.** 5/5 checks passed
(`ghcr.io/timowilhelm/local-neon-http-proxy:main` + `postgres:16-alpine`, repo's
own drizzle + @neondatabase/serverless):

1. `db.transaction()` throws with message exactly
   `No transactions support in neon-http driver` — byte-identical to the pin at
   `server/lib/transaction-support.ts:14`.
2. Data-modifying CTE chain is atomic (FK-violating trailing CTE rolled back the
   leading insert).
3. Guard-fenced chain: guard CTE selecting zero rows produced zero dependent
   writes.
4. `SELECT ... FOR UPDATE` guard CTE driving dependent writes works in one
   statement.
5. Sequential statements are autocommit — non-atomic, as the plan's forbidden
   fallback predicts.

Operational caveats recorded for Phase 2 CI wiring: proxy start-order
sensitivity (mock control plane caches a failed backend DNS lookup until restart
— the lane must healthcheck-gate proxy start on Postgres readiness);
`db.localtest.me` is public wildcard DNS to 127.0.0.1 (offline runs need a hosts
entry). Spike artifacts live in the `Updog_restore-wt-neon` worktree
(`spikes/neon-proxy/`).

Additional confirmed failure modes (evidence for G2):

- **planning-fmv stuck-pending**: the service inserts a `pending` idempotency
  request row before the txn; the neon-http driver throw is not a
  `PlanningFmvOverrideError`, so the catch
  (`planning-fmv-override-service.ts:448-472`, verified) skips
  `markRequestFailed` and rethrows — the row stays `pending` forever and every
  same-key retry gets a permanent 409 `planning_fmv_request_pending`. This is
  the plan's claim-atomicity invariant failing in production **today**.
- **KPI CSV import amplification**: `kpi-observations.ts:295-305` only absorbs
  service-typed errors; the driver throw escapes the per-row catch, so the whole
  import 500s on the first row.

**G2-2 — Class-(b) architecture (the driver decision).** 28 Vercel-reachable
