## Solution Architecture

One guarded deletion with the F_1.24.2 removal gate, adjusted for this ref:

| F_1.24.2 gate item                     | How it is met here                                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1. Tip and reflog-only commits bundled | Existing backup bundle advertises the exact tip; no reflog-only commits exist                               |
| 2. Checksum, verify, restore test      | Backup `SHA256SUMS`; `git bundle verify` rerun; owner scratch drill passed; in-place command proven in 1c   |
| 3. Tip equals bundled SHA              | Enforced atomically by the expected-old-value argument of `git update-ref -d`                               |
| 4. No worktree checkout                | Pre-delete and post-delete worktree scans, with checkout switches paused (replaces `git branch -D` refusal) |
| 5. Owner approval in chat              | Discovery answer authorized this one ref; the TRIP approval gate confirms execution                         |

**Why the worktree scan stays separate.** `git update-ref -d` checks the old
value under the ref lock but, unlike `git branch -D`, does not refuse a branch
that some worktree has checked out. The owner chose the atomic tip check and
covers the checkout race with a pause plus scans before and after. If the
post-delete scan finds a worktree on the branch, the ref is recreated at once
with `git update-ref refs/heads/<name> <full-sha> ""` (the objects are still
present; no gc runs) and the run stops.

**Config and reflog.** Deleting the ref with `update-ref` also deletes its
reflog file but leaves the `branch.<name>.*` config section. Removing that
section completes the branch deletion as `git branch -D` would. This removal is
an addition to the owner's stated command, and the execution approval names it
explicitly. The reflog is preserved byte for byte in the backup
(`git-state/branch.reflog`, covered by `SHA256SUMS`). The config section's two
values are recorded in this plan (Problem Statement); the backup
`git-state/branch-config.txt` matches them but is not checksummed, so restore
uses the values recorded here.

**Record keeping and restore.** The backup directory is not modified. The
execution record is this plan's checked to-dos plus the session report.

- Tested restore: the owner's drilled scratch-checkout recipe in the backup
  `RECOVERY.md`.
- In-place restore (this shallow repository):
  `git -c gc.auto=0 -c maintenance.auto=false fetch --update-shallow --no-tags <backup>/branch.bundle refs/heads/claude/branch-cleanup-audit-plan-d2235d:refs/heads/claude/branch-cleanup-audit-plan-d2235d`,
  then set the two config values recorded above. Step 1c runs this exact command
  text against a temporary ref before deletion. That proves the bundle reads and
  the fetch succeeds against this shallow repository; it cannot prove object
  transfer after gc, because the objects are present today.
- Fast path while objects remain (no gc runs here; unreachable objects outlive
  Git's two-week prune expiry):
  `git update-ref refs/heads/claude/branch-cleanup-audit-plan-d2235d c14f8366a77af9233f333512867c6791f3b4997d ""`.

Restore the branch before unarchiving the PR #1712 session, because that session
expects the branch to exist.

## Implementation Details

### 1. Pre-delete recheck (read-only, immediately before deletion)

The owner keeps every other Claude and Codex session on this repository idle
from step 1a until step 3 finishes.

a. App references: list sessions with archived ones included and a `limit` above
the storage report's session count (440 on 2026-11-18), and confirm the returned
rows cover every session (session count minus this session). A paged or
truncated list fails the check. No non-archived session names
`claude/branch-cleanup-audit-plan-d2235d`, the PR #1712 session is archived and
not running, and the storage report still lists zero worktrees kept after
archive. A session whose worktree was cleaned up can name the branch without any
worktree, so step 1e alone does not cover this. b. Backup integrity:
`shasum -a 256 -c SHA256SUMS` passes in the backup directory;
`git bundle verify <backup>/branch.bundle` passes when run from inside this
repository (the backup directory is not a repository, so verify fails there);
and `git bundle list-heads` prints exactly the full tip and ref. c.
Restore-command proof: run the in-place restore command text from "Record
keeping and restore" with the destination
`refs/archive-tmp/pr1712-restore-proof` instead of the branch ref. Confirm
`git rev-parse` of the temporary ref prints the full tip, delete it with
`git update-ref -d refs/archive-tmp/pr1712-restore-proof <full-sha>`, and
confirm `git for-each-ref refs/archive-tmp/` prints nothing. Any failure stops
the run before deletion.

Steps 1d through 1g and step 2 run in one fail-fast shell invocation, so the gap
between the last check and the delete is a few milliseconds. The invocation
first records `git status --porcelain=v1 -uall` for the step 3 comparison:

d. `git rev-parse --verify refs/heads/claude/branch-cleanup-audit-plan-d2235d`
prints `c14f8366a77af9233f333512867c6791f3b4997d`. e.
`git worktree list --porcelain` contains no
`branch refs/heads/claude/branch-cleanup-audit-plan-d2235d` line. f. The live
reflog file under `$(git rev-parse --git-common-dir)/logs/refs/heads/` is
byte-identical (`cmp`) to the backup `git-state/branch.reflog`. g.
`git config --get-regexp` for the branch section prints exactly the two values
recorded in the Problem Statement.

Any mismatch stops the run before deletion and is reported. Nothing is recreated
or edited.

## Technical Considerations

- **Pattern usage**: F_1.24.2 removal gate, archive-before-delete, and
  restore-from-bundle; AGENT-SAFETY.md branch rules (no `reset --hard`, no
  `git add -A`, no force).
- **Governing policy**: local ref deletion only. No provider mutation, no remote
  push, no Neon or Vercel interaction.
- **Atomicity limit**: the tip check is atomic; the checkout check is not. The
  pause plus pre and post scans plus immediate recreation cover the remaining
  window, as the owner chose.
- **Edge cases**: the tip moved (update-ref refuses; report); the ref is already
  gone (precheck d fails; report, no action); the backup fails its checksum
  (stop; the ref stays); someone unarchives the PR #1712 session later (restore
  the branch from the bundle first).
- **Public repository**: names the branch, its SHAs, and the backup directory
  under `~` only, matching F_1.24.2 practice; no session IDs or file contents.
- **Workflow**: no code edits or tests beyond the router index regeneration, so
  no Hermes dispatch is required. Git operations run in this session.
