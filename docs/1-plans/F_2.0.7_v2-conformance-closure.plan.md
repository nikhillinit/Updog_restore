## Overview

Close the remaining V2 conformance defects before any durable V2 execution
(F2.1) is planned or implemented. All work is engine-internal under
`shared/lib/internal-economics/v2/` and `shared/contracts/internal-economics/`,
plus tests and fixtures. V2 remains computation-only: no routes, persistence,
queues, migrations, flags, workers, or activation.

Success means:

- The missing-versus-ineligible lot refusal precedence is explicitly ratified
  (A1) and then enforced so allocation order cannot change the winning refusal
  (A2).
- Caller-supplied event amounts are positive magnitudes; direction derives only
  from `kind` (A3).
- `expenseCategory: "other"` requires a trimmed, non-empty description (A4).
- The receipt discloses deterministic, conserved fund-level expense totals by
  category (A5).
- Every refusal test proves complete before/after state equality over the full
  `EventStreamState` (A6).
- The receipt-contract and identity-version transition is explicit, with a
  canonical changed-case hash transition and one recorded reason per changed
  hash (A7).
- Merge remains source admission only; production stays separately authorized.

## Problem Statement (defects verified at baseline `aa355aaf7`)

- **A2 — refusal-order defect.** `processFundExpense`
  (`shared/lib/internal-economics/v2/event-stream-engine-v2.ts:962-995`) skips
  missing lots via `continue` (`:978`), refuses on a known-but-ineligible lot
  (`:979-986`), and only afterwards runs the generic existence check
  (`validateCashSourceAllocations`, `:990`). Consequence: a mixed
  missing+ineligible allocation list produces a different winning refusal
  depending on allocation order — ineligible-first wins if it precedes the
  missing reference in iteration. The in-code comment (near `:968`) claims
  "Eligibility precedes generic amount/balance validation … (F_2.0.0 normative
  rule). Unknown lots fall through to the generic existence refusal below" —
  i.e. the code asserts eligibility-first as normative, the direct opposite of
  the counter-proposal's invariant. F_2.0.0 lines 280–337 establish the
  eligible-lot restriction and the refusal code but are silent on ordering, so
  this is a genuine open decision (A1), not a mechanical bug fix. Documented
  intent anchor: `docs/2-changelog/w6_v2.0.6.md:48-53` records "unknown lots
  still take the generic existence refusal" for the same-release precedence
  follow-up — an intent the mixed missing+ineligible case violates in code
  today, which A1's ratification must either uphold or explicitly supersede.
- **A3 — signed-amount admission.** `MoneyDecimalStringSchema`
  (`shared/lib/decimal-string.ts:6-9`) uses regex `^-?(?:0|[1-9]\d*)\.\d{6}$`,
  which admits negative values and `0.000000`. F_2.0.0 declares amounts positive
  magnitudes with direction from `kind`, so a signed or zero caller amount is a
  conformance gap at the validation boundary for caller-supplied `V2Event`
  amounts. Engine-derived directional accounting rows (journal postings, signed
  ledger effects) are out of scope for this tightening.
- **A4 — unconditional optional description.** The `fund_expense_payment` event
  schema declares `description: z.string().optional()`
  (`shared/contracts/internal-economics/internal-economics-input-v2.contract.ts:334`)
  with no conditional requirement when `expenseCategory` is `other`.
  `V2_EXPENSE_CATEGORIES` (`:116`) = `legal | audit | admin | custody | other`.
  F_2.0.0 declares "`other` requires a non-empty `description`" — normative but
  unenforced.
- **A5 — missing category grouping.** No `byCategory` or
  `expenseTotalsByCategory` field exists anywhere in
  `shared/lib/internal-economics/v2/` or `shared/contracts/internal-economics/`
  (verified by repo-wide search at baseline). F_2.0.0's receipt-grouping purpose
  for the category enum is therefore undisclosed.
- **A6 — incomplete refusal-state assertions.** This is a certification gap, not
  a proven engine rollback defect: `cloneEventStreamState` already covers
  `cumulativeExpenses`, `consumptionRecords`, and `eventEffectRecords`, while
  the equality-snapshot helper `snapshotState`
  (`tests/unit/internal-economics/v2/event-stream-atomicity-v2.test.ts:30-116`)
  omits them — so a mutation in an omitted field would pass today's assertions.
  Claim an implementation failure only if an expanded test demonstrates drift.
  The snapshot must cover every field of `EventStreamState`
  (`event-stream-engine-v2.ts:428-442`): `cashSourceLots`, `investmentLots`,
  `callableTrackers`, `partnerLedgers` (every field, including
  `cumulativeExpenses`), `consumptionRecords`, `eventEffectRecords`,
  `partnerEffectRecords`, `derivedEvents`, `endingCash`, `openingCashLots`,
  `openingInvestmentSlices`, `openingEntitlementPools`, `openingJournal` — plus
  any field present at implementation head. A regression in any mutable field
  must fail one runnable test.
- **A7 — version tuple to transition.** Current: accepted input contract
  `internal-economics-composite/2.0.1`; receipt contract
  `internal-economics-receipt/2.2.0`
  (`internal-economics-receipt-v2.contract.ts:8`); waterfall contracts 2.2.0
  (`waterfall-deal-by-deal-v2.ts:18`, `waterfall-whole-fund-v2.ts:20`);
  composite implementation, event-engine, and receipt-serializer identities
  2.2.1 (`derive-composite-v2.ts:38`, `event-stream-engine-v2.ts:23`,
  `liquidity-receipt-builder-v2.ts:46`).

### Batch A2 — Repair missing-reference precedence

Gated on A1. Target: `processFundExpense` (`event-stream-engine-v2.ts:962-995`)
and any sibling processor sharing the same allocation-validation shape.

Required processing order (as proposed by the counter-proposal; final order is
whatever A1 ratifies):

1. Validate every referenced lot exists.
2. If any lot is missing, return the existing generic missing-lot refusal.
3. Validate every existing lot is an event-origin settled-contribution lot.
4. Validate row amounts and aggregate balances.
5. Validate allocation total equals event amount.
6. Apply staged mutations.

- [ ] Expected-red tests first (against the A1-ratified ordering): missing lot
      first + ineligible lot second; ineligible lot first + missing lot second;
      multiple missing lots; existing ineligible opening-cash lot; existing
      ineligible realization-proceeds lot; overdrawn eligible lot.
- [x] Reorder validation per the ratified ADR; update the `:968` comment to cite
      the ADR.
- [ ] Every refusal test asserts complete before/after state equality (Batch A6
      snapshot).

Exit condition: allocation order cannot change the winning refusal.

### Batch A3 — Enforce positive event magnitudes

Apply positivity to caller-supplied `V2Event` amounts only — not to
engine-derived directional accounting rows, journal postings, or any signed
receipt field.

- [x] `0.000000` refuses; negative values refuse; positive six-decimal values
      remain accepted.
- [x] Direction continues to derive exclusively from `kind`; derived event
      generation remains unchanged.
- [ ] Every caller event kind receives table-driven coverage (all 7 admitted
      kinds plus the 2 reserved refusals in `V2EventKind`).
- [x] Implementation point decided at TRIP-2 within the A1 matrix: a

```
  legal: MoneyDecimalString;
  audit: MoneyDecimalString;
  admin: MoneyDecimalString;
  custody: MoneyDecimalString;
  other: MoneyDecimalString;
}
```

- [x] Always emit all five keys; six-decimal canonical strings; absent
      categories emit `0.000000`.
- [x] Conservation: the five-key sum equals the journal `fund_expenses` account
      total, equals total partner `cumulativeExpenses`, and equals the admitted
