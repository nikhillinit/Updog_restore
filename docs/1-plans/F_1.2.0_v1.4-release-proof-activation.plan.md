# v1.4 Full-Surface Release Proof & Current-Forecast Activation — Master Implementation Plan

Version: F_1.2.0 (master program plan; child plans F_1.2.x authored as separate
TRIP-1 passes as gates open)

## Overview

v1.4.0 is tagged (`d030a803`, main) but not released: canonical prod
(`https://updog-restore.vercel.app`) still serves 1.3.2 at SHA `06843072`; no
`Release Production` workflow run exists for `d030a803`. This master plan
sequences the work required to prove every v1.4 surface, repair the Neon HTTP
transaction defects that block one-way current-forecast activation, execute the
governed canonical release, and reach human-authorized activation after a
four-window shadow soak. It supersedes the stale F_1.2.0 draft
(`.worktrees/trip-forecast-activation/docs/1-plans/F_1.2.0_deployment-soak-activation.plan.md`),
which is keyed to ancestor `a3d0a6b6` and incorrectly claims all runtime code
landed.

## Problem Statement

1. **Release drift**: prod serves 1.3.2; v1.4.0 exists only as a tag plus a
   non-production Vercel deployment (`target=null`, unhealthy preview).
2. **P0 transaction defects**: Vercel selects the Drizzle neon-http driver
   (`server/db.ts:61-75`), which cannot run callback transactions. Three
   confirmed P0 paths use raw `database.transaction(...)`:
   - mode update: `server/services/fund-calculation-mode-service.ts:869`
   - pointer advance:
     `server/services/current-forecast-reference-service.ts:342`
   - activation: `server/services/current-forecast-reference-service.ts:607`
     None are covered by the `server/lib/transaction-support.ts` autocommit
     fallback (3 call sites only; and the fallback matches the driver error by
     exact string equality — fragile).
3. **Wider than reported**: ~45 server files (40 under `server/services/` at
   audit time; the child plan derives the exact inventory fresh at dispatch,
   never from this pinned count) call `.transaction(`. Four LP-reporting
   services are confirmed-broken on Vercel — their local `withTransaction`
   helpers use a capability check (`typeof .transaction === 'function'`) that
   passes on neon-http and then throws at call time:
   `metric-run-lifecycle-service.ts:67` (approve `:288`, lock `:364`),
   `metric-run-evidence-service.ts:66,274`, `report-package-service.ts:95,582`,
   `narrative-run-service.ts:114,653,732,819`. All Vercel-reachable (e.g.
   `server/routes/lp-reporting/metric-runs.ts:401,416,445`).
4. **False-green test surface**: zero integration coverage of real neon-http
   behavior (unit tests mock the driver error;
   `tests/integration/current-forecast-reference.pg.test.ts` runs real Postgres
   where transactions work). Closest e2e scaffolds have fatal caveats:
   `tests/e2e/manual-gp-live-proof.spec.ts` forges HS256 JWTs (`:38-62`) and is
   manual-only; `tests/e2e/lp-reporting-package-flow.spec.ts` runs
   `REQUIRE_AUTH:'0'` + memory storage + no queues. Governed production smoke
   (`tests/smoke/production-boundaries.spec.ts`) is request-fixture only — no
   browser mutations.
5. **No async lifecycle proof**: `calculating` status is derived
   (`fund-scenario-calculation-status-service.ts:44-52`), never sampled by the
   existing integration test; `workers/fund-scenario-calc-worker.ts:57`
   `lockDuration` is a lease, and no hard job timeout exists on this path.
6. **Identity gaps**: `/api/version` commit field is shadowed
   (`server/routes/health.ts:526` mounted at `server/app.ts:166` wins over the
   commit-bearing handler at `app.ts:213-219`); Node pins drift (workflow
   `20.19.0`, `.nvmrc` `v20.19.5`, smoke jobs via composite action); Railway
   worker config unproven for the release SHA.
7. **Governance drift**: stale F_1.2 draft, #1298 wrong runbook ref, #1299
   missing current latch semantics, #1325 open despite merged implementation,
   #1317–#1321 mislabeled.

## Decisions Locked (user, 2026-08-05)

1. **Environment ladder, rung 2 (disposable environment) skipped**:
   local/container proof → governed canonical staged release (`--skip-domain`) →
   promotion + post-promotion checks → shadow soak → human-authorized
   activation. Mitigation: extend the staged-smoke job (which runs against the

   tenant/fund; canary data tagged and excluded from reporting; no deletion
   endpoints built. Zero-residue is replaced by a **bounded-residue assertion**
   (tag + count check post-run).
2. **Transactions: audit-first, mixed**. Classify all Vercel-reachable mutation
   paths; P0 paths get atomic SQL/CTE rewrite; adopt a transaction-capable
   driver only if the audit shows broad need. Never widen the autocommit
   fallback to operations requiring atomicity.
3. **Portfolio-company edit IS in the v1.4 contract** — build endpoint + UI
   (product expansion accepted).
4. **Deliverable: master plan + child stubs**; children authored when upstream
   decisions/artifacts close.

## Solution Architecture

Seven workstreams (WS) plus a parallel governance track, gated G1–G5. Stop
condition honored: no executor handoff on a child plan until its upstream gate
closes — the surface matrix must reach zero unclassified rows (G1) and the
transaction architecture must be ratified per-path (G2) before repair tasks are
written.

```
WS1 surface matrix --G1--> WS3 closure packs (incl. portfolio edit)
WS2 txn audit --G2--> WS2b txn repair -+
WS4 canary suite <-- WS3 --------------+
WS5 release identity fixes ------------+--> G3 local/CI green
                                       +--> WS6 governed release (staged canaries -> promote) --G4--> WS7 soak + activation --G5 (HITL #1299)
WS-G governance repair (parallel, closes before G4)
```

### WS4 — Bounded Canaries + Async Proof (child plan D)

**Current evidence / gap**: see Problem Statement 4–5.

**Work**: separate bounded canaries, then one thin aggregate smoke:

- real-login canary (real CSRF + `POST /api/auth/login` — NOT forged JWT; evolve
  `manual-gp-live-proof` mutation coverage onto the `production-boundaries` auth
  pattern),
- fund create/finalize + persistent reload,
- portfolio edit (from WS3),
- modeling readiness (authoritative results),
- report/export,
- deployed-worker lifecycle: enqueue → persisted `queued` → **observed
  `calculating`** → `succeeded`; plus controlled failure, retry, and timeout
  cases. Constraint (Codex-verified): the `calculation_started` event currently
  commits together with completion, so mid-flight polling cannot observe it —
  the worker must **commit the start event in its own statement/transaction
  before computation** so `calculating` is durably observable, not sampled by
  luck.

Add a **hard job timeout** to the `fund-scenario-calc` path (copy the
AbortController pattern at `server/queues/backtesting-queue.ts:268`) —
`lockDuration` is a lease, not a timeout, and the Zero Tolerance policy requires
all queue jobs to have timeouts. The abort signal must **propagate into the
reserve-calculation persistence path with fencing**, and a test must prove a
timed-out attempt cannot subsequently publish `succeeded` (no
timeout-then-success race). Evidence requirements: correlation IDs, deployed
API/worker SHA capture, persistent Postgres (never memory mode —
`server/storage-runtime-policy.ts`). Cleanup: per the locked canary-data
strategy, staged-environment canaries write only to the tagged smoke tenant and
end with a bounded-residue assertion instead of deletion; local/CI canaries tear
down via testcontainers disposal.

**Smoke-tenant contract** (child plan D must specify all five): (1) durable
marker — dedicated smoke user plus a queryable marker on smoke-created
funds/companies (naming convention at minimum; dedicated column/tag if the WS3
migration can carry it); (2) numeric bound — `residue <= N` assertion per run
with a cumulative cap and retention scope (periodic manual purge acceptable);
(3) reporting exclusion — smoke-marked data excluded from GP-facing
listings/aggregates, with tests (fund listing currently returns ALL funds —
exclusion is real work, not a convention); (4) grant flow — login only reloads
**persisted** grants (`server/routes/auth.ts:117`) and fund creation inserts no
creator grant (`server/services/fund-persistence-service.ts:157`), so
re-authentication alone cannot reach a canary-created fund. Child plan D must
resolve this with one of two strategies: (a) **atomic creator-grant persistence
on fund create** (preferred — the gap also affects real users and was masked by
the forged-JWT scaffold; user decision, since it is a product change), or (b)
pin the smoke user to the **`admin`** role, whose access does not depend on
per-fund grants (NOT `service` — fund finalization authorizes only
`partner`/`admin`, `server/routes/fund-config.ts:14`). A pre-granted smoke fund
cannot prove the mandatory new-fund create/finalize/reload path (omitting
`draftFundId` creates a new ungranted fund, `fund-persistence-service.ts:365`)
and is supplemental at most. Forged in-browser token re-minting is forbidden in
all cases; (5) marker/query contract documented so soak/ops tooling can filter
smoke data.

**Acceptance**: each canary green locally/CI (testcontainers) AND against the
staged deployment (G4 pre-promote). Runs on pinned Node 20. **Risk**: canary
flake against staged env — bound retries, fail-closed. **Rollback**: n/a
(test-only) except worker timeout change (forward revert).

## Technical Considerations

- **Pattern usage**: the PATCH endpoint lands inside the already-registered
  `portfolio-companies` router (no new manifest/impl-map/group-slice entries —
  only a route-policy entry for the new method, per WS3); mutations idempotent
  with optimistic locking (Zero Tolerance policy); job timeout copies the
  backtesting-queue AbortController pattern.
- **Neon semantics**: single-statement CTEs are atomic on neon-http; the audit
  must prove each rewritten path fits one statement or escalate to the driver
  decision — never emulate atomicity with sequential autocommit statements.
- **Preact production bundle**: any new client UI must be preact/compat-safe
  (dev runs React, prod ships Preact — ARCHI §1).
- **Edge cases**: concurrent pointer advance vs activation; same-key replay of
  activation; worker crash mid-`calculating`; staged deploy healthy but env vars
  missing (the preview-500 failure class).
