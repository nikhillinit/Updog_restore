## Overview

The `/forecasting` route already reads investment events admitted to the
terminal financial-facts publication
(`server/services/published-investment-comparison.ts`). The analytics dashboard
(`/dashboard?tab=overview|performance`, rendered by
`client/src/pages/dashboard.tsx` -> `dashboard-modern.tsx`) and the shared
`DynamicFundHeader` still read only the legacy unified metrics endpoint
`GET /api/funds/:fundId/metrics`, whose `ActualMetricsCalculator` derives both
`totalCalled` and `totalDeployed` from the legacy `investments` table and NAV
from registry valuations. For a fund whose investments were admitted only
through the actuals publication, the dashboard shows zero deployment and derived
called/uncalled/NAV/return figures that no admitted evidence supports.

This plan adds a publication overlay to the unified metrics response and makes
the dashboard and header consume it. It does not change the legacy calculator,
variance, projections, or the dual-forecast path.

Evidence (local, not in the repository):
`$HOME/.codex/task-artifacts/updog-owner-model-acceptance-20261103/` (accepted
owner-model run, source oracle under `source/`), and
`$HOME/.codex/task-artifacts/forecast-published-investments-repair-20261103/repair-report.md`

## Problem Statement

1. Investment truth: dashboard deployment and company counts ignore the admitted
   publication.
2. Population confusion: "Active companies" and "Avg check size" use the
   registry company population, not cash-invested companies.
3. Unsupported claims: called = deployed, uncalled = commitment - deployed, NAV
   from registry marks, TVPI/DPI/RVPI/IRR from those values. An investment-only
   publication supports none of these.
4. Governed values are not a safe substitute: when an upload declares complete
   ledger coverage with no paid-in or distribution rows,
   `shared/lib/financial-facts/actuals-calculator.ts` reports `paidInCapital`
   and `distributionsToPartners` as available zero. The dashboard must not
   present that as certified zero.
5. Caches: `useFundMetrics` key `['fund-metrics', fundId, ...]` is not
   invalidated by publish/restatement, and the route sends
   `Cache-Control: private, max-age=60`.

## Decisions

- D1 Overlay, not replacement. `ActualMetrics` stays numerically unchanged. A
  new optional `publishedActuals` block is attached to `UnifiedFundMetrics`.
  `null`/absent means no actuals publication applies (no terminal head, or an
  older Round/FMV snapshot without `capitalActuals`); consumers then render the
  legacy lane exactly as today.
- D2 Fresh read outside the aggregator cache. The block is computed on every
  request at the public `getUnifiedMetrics` boundary, after the cached or
  rebuilt legacy object is obtained, and attached by object spread. The
  in-memory cache stores objects by reference, so the cached object must never
  be mutated.
- D3 One core reader. Split `readPublishedInvestmentComparison` into a core
  reader (terminal head -> parse -> `cash_flow_events` provenance rows ->
  validated `PublishedInvestment[]` with `vehicleId`) used by both the existing
  comparison (behavior byte-identical, all vehicles) and the new dashboard
  reader.
- D4 Vehicle scope. The dashboard reading counts only events on the fund's
  active `main_fund` vehicle. Events on other vehicles are excluded and
  disclosed with a count. No main-fund vehicle -> `unavailable` with reason.
- D5 Non-investment metrics. While `publishedActuals` is present, called,
  paid-in, uncalled/dry powder, NAV, total value, distributions, unrealized
  gain, TVPI, DPI, RVPI, and IRR render as unavailable with
  `publishedActuals.unsupportedReason`. Reason text depends on the publication's
  series event types: investment-only -> "This publication admits investment
  transactions only; capital calls, paid-in cash, valuations, and distributions
  need separate admitted evidence."; otherwise -> "The dashboard does not yet
  reconcile this publication's capital-call, valuation, or distribution
  evidence. Review it under LP reporting actuals."
- D6 Commitment stays the fund-record amount (`actual.totalCommitted`), labeled
  as the fund record. Deployment rate = published main-fund deployment /
  fund-record commitment, labeled as such.
- D7 Populations stay distinct: published transactions, published cash-invested
  companies, and registry companies (active/exited/written off) are separate
  labeled values. Average check = published deployment / published cash-invested
  companies.
- D8 `unavailable` never falls back to legacy figures. When
  `publishedActuals.status === 'unavailable'`, investment tiles show the reason
  and no legacy deployment number.
- D9 Historical cutoff: the dashboard is a current reading (terminal head,
  today's date, existing coverage-end disclosure). No `asOfDate` parameter is
  added to the unified endpoint; historical slicing stays on `/forecasting`.
- D10 Reader failure (unexpected error while reading the head or rows) yields
  `status: 'unavailable'` with a generic reason and a server log line; it does
  not fail the whole metrics request.

## Solution Architecture

```
GET /api/funds/:fundId/metrics
  -> current-forecast-serving-seam.getUnifiedMetrics
     -> metricsAggregator.getUnifiedMetrics           (public wrapper, new)
          legacy = buildOrReadCachedUnifiedMetrics()  (existing body, cached)
          published = readPublishedFundActuals(fundId) (fresh, never cached)
          return published ? { ...legacy, publishedActuals: published } : legacy

readPublishedFundActuals / readPublishedInvestmentComparison
  -> readPublishedInvestmentFacts(fundId)   (core, D3)
       none | legacy-snapshot | unavailable(basis?, reason) | facts(basis, investments, eventTypes, warnings)
```

Client: `useFundMetrics` fetch uses `cache: 'no-store'`. Publish and restatement
successes invalidate `['fund-metrics', receipt.fundId]`. `dashboard-modern.tsx`
panels and `DynamicFundHeader` view-model read `publishedActuals` when present.

## Implementation Details

### 1. Contract (`shared/contracts/dual-forecast/investment-comparison.contract.ts` or a sibling)

`PublishedFundActualsSchema` (Zod, strict), type-only on the client:

- `contractVersion: 'published-fund-actuals/1.0.0'`
- `status: 'available' | 'unavailable'`
- `asOfDate` (reading date), `basis` (same shape as comparison basis, nullable)
- `vehicleScope: 'main_fund'`
- `investments: PublishedInvestmentTotalsSchema | null`
- `reason: string | null` (why investments are unavailable)
- `unsupportedReason: string` (D5)
- `disclosures: string[]` (coverage end, excluded vehicles, publication
  warnings)

`UnifiedFundMetrics.publishedActuals?: PublishedFundActuals | null` (optional;
`exactOptionalPropertyTypes` safe).

### 2. Core reader and dashboard reader (`server/services/published-investment-comparison.ts`)

- Extract the head/parse/provenance logic into `readPublishedInvestmentFacts`.
  Keep every existing validation (fund match, USD, approved/locked,
  `portfolio_investment`, vehicle/perspective/date/amount equality, payload
  parse, non-null deployment category) and the existing reasons.
- `readPublishedInvestmentComparison` keeps its signature, return values, and
  disclosures exactly.
- New `readPublishedFundActuals(fundId, now = new Date())`: returns `null` for
  none/legacy-snapshot; otherwise resolves the active `main_fund` vehicle,
  filters investments to it, aggregates with `aggregatePublishedInvestments` at
  today's date, and builds the block per D4/D5/D8/D10.

### 3. Aggregator overlay (`server/services/metrics-aggregator.ts`)

Rename the existing body to a private method; the public `getUnifiedMetrics`
wraps it per D2. The serving seam and route stay unchanged.

### 4. Client cache (`client/src/hooks/useFundMetrics.ts`, `client/src/hooks/lp-reporting/useActualsPublish.ts`, `useActualsRestatement.ts`)

`cache: 'no-store'` on the metrics fetch; add `['fund-metrics', receipt.fundId]`
invalidation beside the existing `['dual-forecast', receipt.fundId]` calls.

### 5. Dashboard (`client/src/pages/dashboard-modern.tsx`)

When `publishedActuals` is present:

- Overview: fund-record commitment; published deployment with rate label;
  published cash-invested companies; registry companies (active of total).
- Capital structure: commitment and published deployment (initial, follow-on;
  secondary/other only when present and nonzero) with a deployed-only progress
  bar; called, dry powder, distributions unavailable (D5).
- Portfolio composition: registry status breakdown labeled as registry;
  transaction count; average check per cash-invested company.
- Performance snapshot and performance tab: all return/value tiles unavailable
  (D5).
- One source line per card: publication snapshot id, data-through date, and
  knowledge cutoff, plus disclosures.
- `status === 'unavailable'`: investment tiles show `reason` (D8).

Absent `publishedActuals`: render exactly as today. Use `presson.*`/existing
tokens only (`DESIGN.md`); no new React-only APIs (Preact production bundle).

### 6. Header (`client/src/lib/fund-header-metric-calculations.ts`, `client/src/components/layout/dynamic-fund-header.tsx`)

When `publishedActuals` is present: deployment rate from published main-fund
deployment over fund-record commitment; remaining, NAV, TVPI, DPI, and IRR
unavailable. Absent: unchanged.
