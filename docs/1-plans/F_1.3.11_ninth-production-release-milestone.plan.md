## Problem Statement

1. ADR-116 is not in effect. Without it, ADR-115 is not in effect, and no 0062
   window may open. The #1720 description also shows ADR-118 text under the
   ADR-116 ratification heading, which misleads any later reader.
2. The stored Railway token has never been checked under ADR-118. Every release
   mode and the step 2 capture need it.
3. ADR-079 makes confirmed Vercel-reachable durable-write guard gaps release
   blockers. 173 such rows exist and the review is open. A gap found after the
   0062 apply would hold production in the mixed state that F_1.3.8 warns about:
   the 0062 trigger running under old code while the 90-day receipt clock runs.
4. Several F_1.3.8 read-only checks (G9, G6, G8) and the F_1.3.9 rollout census
   are scheduled at the window or later. A failure found there costs a window.
5. #1715 shows users generic HTTP text instead of the refusal reason, and the
   definitive-refusal codes that decide whether an attempt key is cleared live
   only in the client panel.
6. No tracked file can record live progress while merges are frozen.

## Solution Architecture

Lanes and order. "Agent" means the executor drafts and verifies locally. The
owner ratifies, merges, approves, dispatches, and performs every provider and
environment action.

```
M0  this plan PR (agent drafts; owner merges)                          TRIP-2
R1  ADR-116 ratification record PR (agent drafts; owner ratifies)      TRIP-2  --+
K   Railway S4 under ADR-118 + F_1.3.8 G2 readings (owner)                       |
A   ADR-079 remaining-write review, fix PRs, closure (agent; owner)    TRIP-2  --+--> W
E   pre-window read-only evidence: G9, G6, G8, census (owner)                  --+
W   0062 window: F_1.3.8 item 8, S5 to S7 (owner)
V   ninth vehicle, release, closeout: F_1.3.8 items 9 to 11 (owner; agent drafts)
P   #1715 repair: built now as a draft PR, merged only after V        TRIP-2
```

R1, K, A, and E run in parallel. W opens only when all four have closed.

Merge gate: every PR from M0, R1, and A merges before W's exact-SHA hold opens
(F_1.3.8 item 8 step 4). A merge after the rehearsal dispatch invalidates the
rehearsal. The A closure PR is the last code-bearing merge before the hold; any
later merge that changes a Vercel-reachable write row reopens A for that row. P
stays a draft PR with auto-merge off from now until V closes out (F_1.3.8 item
11, ADR-103 freeze lift).

Why this order:

- R1 before W: the 0062 route is a ratified ADR-115 as amended by ADR-116. It
  does not exist until ratification is recorded.
- K before W: F_1.3.8's reason stands. A second Railway failure then costs
  nothing on the schema side.
- A before W: a confirmed gap blocks release (ADR-079). Applying 0062 starts the
  90-day receipt clock and runs the 0062 trigger under old production code.
  Finding a gap after apply would leave production in that state while the fix
  goes through review.
- E before W: F_1.3.8 item 8 already requires G9, G6, and G8 read-only results
  before step 1. Running them during A and K uses idle owner time. The census
  joins them because the release carries the F_1.3.9 guards and the A fixes.
- P after V: Q3. It never changes the release candidate or breaks a hold.

Deadlines from F_1.3.8 still bind: release step 8 must finish before the 0062
apply artifact expires (90 days after upload) and before the step 2 capture
artifact expires (30 days after upload).

**Method per row**:

1. Trace the `makeApp` mount to the handler (ARCHI.md section 3; `makeApp` is
   the live production surface).
2. Record exactly one of:
   - Effective write guard: a role guard from `server/lib/auth/jwt.ts` with the
     ADR-072 tuples from `shared/auth/effective-roles.ts`, plus fund write scope
     (`enforceProvidedFundScope(req, res, fundId, { forWrite: true })`) or
     canonical ownership loaded before mutation with the authoritative fund id
     in the SQL `WHERE` (ADR-079 rule 2).
   - Equivalent control: a named control with its source location, for example
     the actuals pilot grant, investor scoping for LP-self rows, a share-token
     check, or session-self logout.
   - Explicit exception: only with an owner decision and a stated reason.
3. A row with none of the three is unresolved. An unresolved row is a confirmed
   gap only when a failing test shows that an authenticated principal without
   the required role or fund write scope can change durable state. Otherwise
   record why the row is safe and add the missing evidence.
4. For `persistence: writes` rows on `GET`, record what is written (for example
   audit rows or read markers) and judge the guard against that write.

**Fix PRs** (one per family, kept small):

- Apply the F_1.3.9 guard chain (the ADR-079 rule 2 pattern, as in
  `server/routes/lp-reporting/imports.ts` after #1719). Do not invent a new
  guard helper.
- Tests: restricted-principal denial with zero mutation (PostgreSQL where the
  route writes SQL) and role-matrix allowed cases.
- Matrix: reseed per the README maintenance recipe, then a scoped review file in
  the shape of the f139 file that lists every row the change demoted (a changed
  route file demotes every row it sources, not only the fixed row), then the dry
  run and the owner-authorized mutation.
- Titles and descriptions use neutral wording ("apply team write guard to ...").
- Stop rule: a gap whose fix falls outside the rule 2 pattern (a contract break,
  a new role, a schema change, a client change, or a change to LP-facing
  behavior) stops for an owner decision. It still blocks release unless the
  owner records an explicit exception in the ADR-079 status note.

**Public-repository rule**: an unfixed gap's row ID and reason never appear in a
tracked file, PR, issue, or commit before its fix merges. The working ledger
stays in private owner evidence until every confirmed gap is fixed on `main`.

**Closure PR** (docs only): a public review ledger
`docs/3-code-review/ADR-079_remaining-vercel-write-review.md` that lists every
row in scope with its recorded guard, control, or exception and the fix PR,
keyed to the closure SHA; an ADR-079 status note in `DECISIONS.md` that records
the closure SHA and the fix PRs, with no counts of open gaps and no
exploitability detail (F_1.3.9 precedent); a governance test pin for that note
if the existing ADR-079 or ADR-117 pins require it; routing regeneration; one
`CHANGELOG.md` note.

**Review closed** means: every row in scope has a recorded guard, control, or
exception at the closure SHA; every confirmed gap's fix has merged with green
current-head `CI Gate Status`; and `validate-matrix.mjs` passes at the closure
SHA. "Fixes in production" (ADR-117) happens only at the ninth release's
promotion. Lifting the ADR-117 access hold after that is a separate owner
decision that this plan does not make.

## Technical Considerations

- **Pattern usage**: route guards follow ADR-072 and ADR-079 rule 2 as applied
  by F_1.3.9. Matrix maintenance follows the README recipe. Mutations keep
  idempotency and optimistic locking (CLAUDE.md non-negotiables); P touches only
  error interpretation, not the idempotent command.
- **Holds and merges**: the S6 exact-SHA hold (at most 72 hours) and the ADR-107
  merge freeze (capture through step 8) are separate. Dependabot PRs follow the
  F_1.3.8 G10 hold list and also never merge during the S6 hold.
- **Matrix side effects**: changing a route file changes its source hash and
  demotes every row it sources. The f139 precedent listed 24 rows for one file.
  Each A fix PR budgets for that.
- **Client bundle**: production ships Preact; P's shared-contract import must
  stay preact/compat-safe and free of Node built-ins (ARCHI.md section 1).
- **Provider drift**: if the token, a service, or the canonical deployment
  changes after K, the step 2 capture refuses. F_1.3.8 item 3's post-apply stop
  rule handles that case.
- **Edge cases**:
  - The owner does not accept the post-admission reading of ADR-116: R1 becomes
    a re-admission PR; W waits.
  - K returns a non-token failure class: stop; separate repair plan.
  - A finds a gap outside the rule 2 pattern: owner decision; release stays
    blocked unless an explicit exception is recorded.
  - The census finds an out-of-set role: stop; fixing the user's role is a
    separate owner action under the provisioning procedure.
  - A merge after the A closure changes a Vercel-reachable write row: A reopens
    for that row before the hold.
  - R1's squash commit lacks the ratification text: the owner records it again
    before W.
