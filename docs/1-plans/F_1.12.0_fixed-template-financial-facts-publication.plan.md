## Overview

One internal fixed-template path turns one ledger CSV plus one valuation CSV
into one immutable policy-1.4 / payload-5 financial-facts snapshot in one
serializable transaction, with database-backed idempotent replay, strong
optimistic concurrency on the facts head, explicit-grant authorization, typed
refusals, and a readback of the published facts. Forecast, reserve, and
construction-reconciliation consumers accept policy-1.4 heads through one shared
codec and name the `FinancialFactsBasisRef` they used; economics and
periodic-analysis consumers refuse payload 5 with a typed reason. No new table,
column, index, migration, queue, worker, dependency, mapping UI, draft state, or
provider action.

```text
ledger CSV (actuals-ledger/1.0.0) [+ valuation CSV (actuals-valuation/1.0.0)]
  -> POST /api/funds/:fundId/imports/actuals/dry-run      preview + hashes, no effect
  -> POST /api/funds/:fundId/imports/actuals/publish      ONE SERIALIZABLE transaction:
        source_artifacts (1-2 rows) + approved cash_flow_events + approved
        valuation_marks + one policy-1.4 financial_facts_snapshots row
  -> GET  /api/funds/:fundId/financial-facts/latest-reference   head + strong ETag
  -> GET  /api/funds/:fundId/actuals/metrics                    projection of one snapshot
  -> forecast / reserve / construction runs read the head via parsePersistedFactsRow
        and carry basisRef; economics / periodic_analysis refuse UNSUPPORTED_FACTS_POLICY
```

## Problem Statement

- Today the only facts writer is the manual
  `POST /admin/funds/:fundId/financial-facts/snapshots` route
  (`server/routes/financial-facts.ts:128`) whose builder reads accepted V2
  observations, working selections, and the legacy per-company calculator; a
  fund with no V2 observation lineage cannot publish a head that forecasts or
  reserves will accept.
- The V1 CSV import routes (`server/routes/lp-reporting/imports.ts:256-402`)
  admit rows but publish no facts snapshot; V2 batch routes (`:404-702`) need a
  mapping profile and reconciliation cases that a fixed template does not need.
- There is no idempotent, lock-proved, restatement-safe way to get real
  capital-call, distribution, fee, investment, proceeds, and valuation actuals
  into a head that downstream tools can name.
- Consumers hard-code accepted policy versions
  (`current-forecast-v2-service.ts: 123-127`,
  `dynamic-reserve-intelligence-service.ts:123-126`,
  `lp-economics-run-service.ts:791`,
  `construction-reconciliation-service.ts: 81-87`), so a new policy silently
  fails to parse instead of refusing with a typed reason.

### Shape

- Preview and publish live in the existing `lp-reporting-imports` router
  (`server/routes/mount-common-routes.ts:111`, manifest
  `shared/routes/api-route-manifest.ts:892`), so no manifest, impl-map, or
  group-slice change is needed; only route-policy entries. Registration is
  conditional on `ACTUALS_PILOT_FUND_ID` inside the router module.
- Payload 5 = payload 4 + `capitalActuals` + `valuationActuals` +
  `admissionReceiptCore`. `cashFlowSeries.series` and `marksSeries.marks` are
  cumulative, rebuilt every publication from the fund's accepted pilot rows and
  marks read under the lock (S8) in the deterministic order the 1.3 builder
  already imposes (only the ordered `series` and `marks` arrays of
  `buildCashFlowSeries` `:283-358` and `buildMarksSeries` `:402-445` are reused;
  totals, `periodNav`, and warnings are payload-5 outputs), because the cohort
  engine derives cumulative values only from the series
  (`CohortProjectionV2.ts:239-265, 283-327`). `periodNav` holds the
  complete-coverage position-value sum (S12) or is empty. `companyActuals` comes
  from the existing per-company producer run inside the transaction with
  `planningMarkSources: ['actuals_pilot_v1']`; `sourceObservationIds`,
  `workingValueSelectionIds`, and `participationTermRefs` are empty.
- `sourceFactsInputHash` preimage = canonical hash of
  `{templateVersions, fundId, asOfDate, ledgerPayloadSha256, ledgerCanonicalRowsHash, valuationPayloadSha256 | null, valuationCanonicalRowsHash | null, coverage, commitmentBasis, predecessorSnapshotInputHash | null, companyActuals.inputHash}`.
  The last member is the content hash the existing producer already emits, which
  keeps the read set bounded and named.
- Consumer evaluations for payload 5 (pure, `shared/`):
  - `forecast`: `accepted` iff ledger coverage complete, valuation coverage
    complete, and `periodNav` non-empty; else `blocked` with
    `ledger_coverage_partial` (V3), `position_valuation_incomplete` (existing V2
    reason), or `period_nav_unavailable` (V3). The cohort engine defaults a
    missing period NAV to zero and still computes TVPI
    (`CohortProjectionV2.ts:268-302`), so an accepted forecast must never run
    without a position-value NAV. The engine also adds `lp_distribution` and
    `realized_proceeds` series into one distributions bucket (`:253-256`), so
    payload 5 emits no `realized_proceeds` series; proceeds live only in
    `capitalActuals`.
  - `reserve`: `accepted` iff valuation coverage complete and every roster
    company has non-empty `investmentIds` in `companyActuals`; else `blocked`
    with `position_valuation_incomplete` or `investment_lineage_unresolved`
    (V3).
  - `economics`, `periodic_analysis`: `blocked`, `unsupported_payload_policy`.
- Lock and transaction: one `fund-lock.ts` helper adopted by the publisher and
  the manual writer; `SET LOCAL` timeouts scoped to the remaining 30 s budget;
  three attempts on `40001`/`40P01`/invisible-winner unique races; S5 recovery
  on ambiguous COMMIT; projection validated before COMMIT.

### 2. Pilot contracts

**File**: `shared/contracts/lp-reporting/actuals-pilot.contract.ts` (new),
re-exported from `shared/contracts/lp-reporting/index.ts` (modify, append one

Strict Zod schemas and inferred types for: `ActualsPreviewRequestV1`,
`ActualsPreviewResponseV1` (ledger and valuation variants discriminated by
`templateVersion`), `ActualsPreviewIssueV1`, `ActualsPublishRequestV1`,
`ActualsPublishReceiptV1`, `FinancialFactsLatestReferenceV1`, `ActualMetricsV2`,
`GovernedMoneyV1`, `GovernedRatioV1`, `ActualsAvailabilityReasonV1`, the error
`details` union, the `If-Match` and `ETag` grammars, and the row-payload JSONB
contracts (`actuals-pilot-cash-flow/1.0.0`,
`actuals-pilot-valuation-mark/1.0.0`). Full definitions are in Type Definitions.
The existing V1 `import-dry-run.contract.ts` and `import-commit.contract.ts` are
not edited.

Lexical grammar (server-enforced, listed here so the parser is unambiguous):

- Exact header order and case; RFC-4180 single-line fields; LF or CRLF, not
  mixed; one optional BOM; no NUL; whitespace-only cell invalid.
- Money `^(?:0|[1-9][0-9]{0,13})(?:\.[0-9]{1,6})?$`, cent-exact
  (`SUBCENT_USD_UNSUPPORTED`); ledger `amount > 0`; valuation
  `position_fair_value >= 0` and `cost_basis` empty or `>= 0`.
- `currency` literal `USD`; dates real Gregorian `YYYY-MM-DD`; ledger
  `effective_date <= asOfDate`; valuation `mark_date == asOfDate`
  (`VALUATION_AS_OF_MISMATCH`), so no admitted mark can post-date the head and
  the producer's `markDate` ordering and the selector's future-mark exclusion
  both see it.
- Closed values: `deployment_category` empty or
  `initial | follow_on | secondary | other` (portfolio_investment rows only);
  `expense_category` `management_fee` on management_fee rows,
  `legal | audit | admin | other` on fund_expense rows, empty otherwise;
  `distribution_type` `return_of_capital | gain | income` and `recallable`
  `true | false` (lp_distribution rows only); `mark_source` one of the ten
  values in the `valuation_mark_source_check` constraint
  (`shared/schema/lp-reporting-evidence.ts:200-203`); `confidence_level`
  `high | medium | low`; `valuation_method` 1-64 formula-safe characters;
  `description` optional, up to 1,000 characters, hash-bearing verbatim.
- `external_ref` `^[A-Za-z0-9][A-Za-z0-9._:/-]{0,127}$`, unique per file,
  case-sensitive; every occurrence of a duplicate is `duplicate_in_file` (no
  first-row winner). Valuation files additionally require one row per
  `(vehicle_slug, company_name)` (`DUPLICATE_COMPANY_MARK`).
- Formula-like first character (`=`, `+`, `-`, `@` after BOM, space, or control)
  rejected in every text cell (`FORMULA_LIKE_VALUE`).
- Structural failure (invalid UTF-8, NUL, mixed endings, unmatched quote,
  alternate delimiter, embedded newline) is HTTP 400 `INVALID_CSV`; wrong header
  is a 200 blocked preview with `INVALID_HEADER` at row 1; wrong width is
  `INVALID_ROW_WIDTH`.
- Decoded byte caps: ledger file 122,880 bytes, valuation file 40,960 bytes,
  combined 163,840 bytes per publish (`PAYLOAD_TOO_LARGE` = 413). Base64 of the
  combined maximum is 218,454 bytes, which stays under the 256 KB JSON body
  limit of `makeApp` (`server/app.ts:138`) and must stay under the `bodyLimit`
  used by `server/server.ts:153`; Phase 5 asserts a maximum-size request on both
  assemblies. Row cap 1,000 per file (`ROW_CAP_EXCEEDED` = 413).
- Identity:
  `canonicalLabel = NFKC -> trim -> collapse whitespace -> locale-independent lowercase`;
  two bounded fund-scoped queries build company and vehicle maps once per
  request; zero matches `COMPANY_NOT_FOUND`, many `COMPANY_NAME_AMBIGUOUS`;
  blank `vehicle_slug` resolves only when the fund has exactly one vehicle and
  it is an active USD `main_fund` (`shared/schema/vehicles.ts:32-60`), else
  `UNSUPPORTED_VEHICLE_SCOPE`.
- Two hash families. Raw bytes: `sha256Bytes(bytes)` implemented twice with
  identical output, server in `server/lib/sha256-bytes.ts` (new, `node:crypto`)
  and client as a new export of `client/src/lib/hash.ts` (`crypto.subtle`);
  `payloadSha256` is `sha256Bytes` over the exact decoded file bytes and is the
  only hash the client recomputes. Canonical objects: the existing server-only
  `canonicalSha256` (`shared/lib/canonical-hash.ts`, `node:crypto`; never
  imported by client code) for every other hash below. A cross-runtime vector
  test pins `sha256Bytes` on both runtimes against fixed byte strings;
  `rowSourceHash = H({fundId, externalRef})`;
  `rowContentHash = H({templateVersion, rowSourceHash, canonicalEconomicFields, resolvedCompanyId, resolvedVehicleId})`;
  `canonicalRowsHash = H({templateVersion, fundId, asOfDate, rows sorted by rowSourceHash then rowContentHash})`;
  `previewHash = H({templateVersion, fundId, asOfDate, payloadSha256, canonicalRowsHash, rowStatusesAndIssueCoordinates, resolvedIdentityPairs, fileTotals})`.
  No `localeCompare`; arrays sort by UTF-8 bytes.

### 6. Pure calculator

**File**: `shared/lib/financial-facts/actuals-calculator.ts` (new).

`ActualsCalculatorInputV1`: cumulative ledger basis (net-new plus predecessor

`DEPLOYMENT_CATEGORY_PARTIAL`), `managementFeesPaid`, `otherExpensesPaid`,
`realizedFundProceeds`, `distributionsToPartners`, `recallableDistributions`.

closed reasons: `calledCapitalIssued`, `netCalledCapital`, `uncalledCapital`,

the ratios `rvpi`, `tvpi`. DPI = partner distributions / settled paid-in as a

`PAID_IN_ZERO` on zero denominator. Truth vectors TV-001..008 and FIN-V001..V004

  SET LOCAL idle_in_transaction_session_timeout = <same>   -- the runtime pools set none of these (see Technical Considerations)
  SELECT pg_advisory_xact_lock(hashtext('financial-facts:' || fundId))
  SET LOCAL statement_timeout = min(10s, remaining); SET LOCAL lock_timeout = min(2s, remaining)
  (remaining < 1 s here or before COMMIT: ROLLBACK, 503 PUBLISH_RETRY_EXHAUSTED)
  replay candidate by (fund_id, idempotency_key)
  lock + revalidate actor, is_active, role, canary flag, grant (FOR SHARE)
  if candidate: actor-first, coherence, request-hash comparison; project; COMMIT (no writes)
  resolve unique terminal head (zero/one/many -> FACTS_HEAD_AMBIGUOUS; lineage walk -> FACTS_LINEAGE_INVALID)
  compare If-Match to head; asOfDate >= head.asOfDate else HISTORICAL_AS_OF_NOT_HEAD_ELIGIBLE

  lock fund, the one vehicle, referenced companies (FOR SHARE); recompute identity + hashes; compare expected hashes
  classify every ledger row and valuation row; any conflict refuses before writes
  insert source_artifacts row(s); insert net-new cash rows as approved; insert net-new marks as approved
  read the cumulative basis under the lock (S8): every cash_flow_events and valuation_marks row of the fund with
    imported_from = 'actuals_pilot_v1' AND status IN ('approved','locked'), with typed payload fields, ordered

    now = captured knowledgeCutoff, and knowledgeCutoff omitted (its createdAt/approvedAt filters at
    fund-company-actuals-facts-service.ts:696-701 would drop rows inserted in this transaction)
  build payload 5 (item 12); evaluate consumers (item 7); compute sourceFactsInputHash + snapshotInputHash
  INSERT financial_facts_snapshots ... RETURNING
  project + strict-parse the receipt while rollback is still possible

Retry and recovery: `40001`/`40P01`, or a unique race whose winner was invisible
to this snapshot, roll back and retry the whole attempt with the same bytes,
hashes, key, tag, and captured `knowledgeCutoff`; at most three attempts; 30 s
monotonic budget across attempts re-read before every `SET LOCAL` and before
COMMIT; exhaustion -> `503 PUBLISH_RETRY_EXHAUSTED` with no effect. Other
SQLSTATEs and local timeouts after the fund lock is held are not retried.
Indeterminate COMMIT follows S5; a resolution transaction becomes the next
numbered attempt and never creates a fourth. Driver fail-closed: when the
connection is the Neon HTTP autocommit driver
(`server/lib/transaction-support.ts` pin), publish refuses before BEGIN with
`503 TRANSACTION_UNSUPPORTED`, matching the F_1.11.0 activation precedent.

`coverage.ledger='inception_to_date'`; equal `asOfDate` may add newly referenced
rows and creates a successor; `incremental_since_prior_head` requires
`priorFactsSnapshotId` equal to the current head and that head to be payload 5
with complete ledger coverage; a payload-1-4 head may be superseded only by an
inception-to-date publication.

Replay: load by `(fund_id, idempotency_key)`; compare stored actor to
revalidated actor first (mismatch -> 404, no receipt); strict-decode payload and
require `core.operationHash === row.request_hash` (mismatch -> 500
`INTERNAL_ERROR`, no repair); compare with the recomputed request
`operationHash` (mismatch -> 409 `IDEMPOTENCY_KEY_REUSED`); project. Replay
never reads current head, scope, or artifact payload, so it survives artifact
purge.

## Technical Considerations

- **Pattern usage (ARCHI.md)**: new routes inside an existing manifest router
  need no manifest/impl-map/group-slice change (section 3); route-policy entries
  are still mandatory. Mutations use database-backed idempotency
  (`server/lib/idempotent-command.ts`, `database-backed-idempotency-routes.ts`).
  Financial math is Decimal only (`guard:decimal-string-laundering:check`). Any
  React API added to the page must be preact/compat-safe (section 1).
- **Driver**: the transaction requires a transaction-capable driver. Vercel runs
  the Neon WebSocket pool (ADR-073); the Neon HTTP fallback in
  `server/lib/transaction-support.ts` cannot hold an advisory lock across
  statements, so publish fails closed (`503 TRANSACTION_UNSUPPORTED`) instead of
  degrading. Usage of `transaction-support.ts` stays fenced by
  `scripts/guardrails/transaction-support-usage.mjs`.
- **Timeouts**: the runtime database handle is `server/db.ts` (node-postgres
  `Pool` locally and on Railway, Neon WebSocket `Pool` on Vercel); neither
  branch sets `statement_timeout`, `lock_timeout`, or
  `idle_in_transaction_session_timeout` at connect time (`server/db/pool.ts` is
  not on this path). The publisher therefore sets all three with `SET LOCAL`
  inside the transaction, scoped to the remaining command budget, and never
  awaits anything but database calls while the transaction is open.
- **S8 amendment cost**: calling `fund-company-actuals-facts-service.ts` inside
  the transaction widens the read set to investments, rounds, and approved
  planning marks. It is bounded by the producer's own `inputHash`, which is
  included in `sourceFactsInputHash`, so reproducibility stays provable. The
  producer is read-only; the transaction stays SERIALIZABLE, so a concurrent
  investment edit surfaces as `40001` and retries.
- **Roster derivation (S12)**: a company that has exited still needs a mark
  (zero is allowed and cites the row); the trial STOP list covers a source that
  needs write-offs or reversals the template cannot express.
- **Position-value NAV (owner-visible design choice)**: no fund-cash or
  liabilities source exists, so true NAV is unavailable. The cohort engine
  defaults a missing period NAV to zero and computes TVPI anyway
  (`CohortProjectionV2.ts:268-302`), which would silently understate every
  forecast. Rather than block forecasts forever, payload 5 supplies `periodNav`
  from complete-coverage marks (the same position-value basis the engine already
  uses for projected NAV at `:465-490`), labels it with
  `PERIOD_NAV_IS_POSITION_VALUE`, blocks forecast whenever coverage is partial
  or marks are absent, and keeps metrics `nav`/RVPI/TVPI `unavailable`. If the
  owner prefers to block forecasts until a NAV source exists, delete the
  `periodNav` population and make `period_nav_unavailable` unconditional; no
  other section changes.
- **JSON body limits**: `makeApp` caps JSON at 256 KB (`server/app.ts:138`) and
  `server.ts:153` uses `bodyLimit`; the per-file and combined decoded caps in
  item 2 are sized so a maximum request fits both without touching the limits.
- **Cross-path duplicates (S15)**: V1 `source_hash` values are not comparable to
  pilot identities, so the lane requires an otherwise pilot-owned ledger and
  mark set for the fund; the trial preflight asserts it. Widening to a
  content-tuple reconciliation is a follow-on if a fund with legacy rows must
  join the lane.
- **Forecast series semantics**: the cohort engine sums `lp_distribution` and
  `realized_proceeds` into one distributions bucket
  (`CohortProjectionV2.ts:253-256`). Payload 5 emits no `realized_proceeds`
  series (proceeds stay in `capitalActuals`), which diverges from the 1.3
  builder's series and is asserted in the consumers PG test: forecast cumulative
  distributions equal partner distributions only.
- **Consumer evaluations**: the legacy evaluator
  (`financial-facts-snapshot-service.ts:548-571`, `:1486`) depends on V2
  observation linkage; payload 5 has none, so a pure evaluator over payload
  content replaces it for policy 1.4 only. Existing V2 reason codes are reused
  where semantics match (`position_valuation_incomplete`); new codes are V3.
- **Cohort engine**: `CohortProjectionV2.ts:206-327, 465-490` reads
  `cashFlowSeries` for cumulative contributions, distributions, and deployed
  capital, `marksSeries.marks` for projected NAV, and `periodNav` for actual
  NAV; Phase 0 characterizes it with a payload-5 fixture that has cumulative
  series and populated `periodNav`. The engine is not patched in this plan.
- **Rate limiter**: `importLimiter` is process-local (resets per serverless
  instance); acceptable pilot abuse control, documented as such.
- **Vercel release path**: `vercel.json:3-5` sets `github.autoAlias: false`, so
  a merge builds a deployment but production promotion happens through the
  separately orchestrated `release-production` workflow. Independently of that
  gate, the routes exist only when `ACTUALS_PILOT_FUND_ID` is set; production
  must not set it until a separate activation authority exists.
- **Migrations 0050-0055 production state**: unknown; irrelevant to this no-DDL
  plan, still a production blocker for other work.
- **Forked head**: a privileged writer that skips the shared lock can fork the
  head; readers fail closed (`FACTS_HEAD_AMBIGUOUS`). Plan A's root partial
  unique index (migration 0056) stays a deferred design, triggered only by such
  a writer appearing.
- **Edge cases**: duplicate `external_ref` across files in one publish (ledger
  and valuation namespaces are separate; the row hash includes
  `templateVersion`); valuation file present with zero roster (ledger has no
  deployments) -> `VALUATION_ROSTER_EMPTY` warning, marks still admitted,
  `portfolioFmv` available at 0 only when the file is empty of rows and the
  roster is empty (cites ledger coverage); equal `asOfDate` successor;
  predecessor is payload 1-4; grant revoked between route check and transaction
  (re-read under lock -> 404, zero writes); a pilot contribution locked through
  the lock route between publications stays in the cumulative basis
  (`status='locked'` is accepted); artifact purged before replay (receipt core
  owns replay); non-UTC process and session timezone (dates persist as exact UTC
  midnight, readback derives from UTC fields).

## Performance & Cost Impact

- Preview: two bounded fund-scoped identity queries plus one
  `(fund_id, source_hash)` lookup batched per file; no per-row queries;
  1,000-row cap per file; response bounded by the row cap.
- Publish: one transaction holding the fund lock for the duration of parsing,
  classification, inserts, the per-company facts read, and the snapshot insert.
  Duration at 1,000 ledger rows plus 100 marks is unmeasured; the PG suite
  records it as a diagnostic (not an assertion) and the trial STOPs above 10 s.
  Concurrent publishers serialize on the fund lock; one wasted attempt under
  contention is expected and retried.
- Consumers: no new queries; the codec replaces per-reader parsing with one
  strict parse per read.
- No new infrastructure, dependency, queue, worker, or provider cost.
