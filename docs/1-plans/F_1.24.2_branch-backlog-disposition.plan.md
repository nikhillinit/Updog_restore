# Branch Backlog Disposition Implementation Plan

## Overview

The November 18, 2026 preserved-branch audit (Codex run
`updog-preserved-branch-cleanup-20261118`, keyed to `main @ 3b9ad1b97`) found
zero deletion candidates. Its only removal gate is complete integration proof,
which 26 local branches cannot pass short of being merged. This plan adds a
second, owner-authorized exit, "bundle-archive then delete", and applies it to
the dormant backlog. It also releases the merged checkouts and settles three
provider branches. No repository code changes; the only tracked artifacts are
this plan and the regenerated router index.

## Owner Decisions (2026-11-18 discovery)

These were settled with the owner before drafting and are not reopened here:

1. Removal gate for dormant unproven branches: bundle-archive then delete
   (verified bundle, restore test, recovery record, per-batch owner approval).
2. Unfinished feature work: hold refs tied to open workstreams (ADR079
   IRR-fixture stack including its WIP scope test, F137 / ADR-114 rotation);
   archive the rest.
3. Merged checkouts: in scope, with per-checkout owner release.
4. Provider branches: in scope, including agent-run remote deletion.
5. Archive root: `~/code/.agent-state-backup/branch-archive-2026-11-18/`; prior
   bundles indexed in place, not moved.
6. Operations only: no repository scripts or code.
7. Hold rule: bundle now, keep ref, review date 2026-12-18.

## Problem Statement

- 26 local branches sit in `investigate` limbo. Re-auditing them produces the
  same verdict each pass (about 25 audit and cleanup runs on 2026-11-17 and
  2026-11-18 alone), at real cost, with no exit.
- Six merged branches stay checked out in registered worktrees, plus two alias
  refs and two detached worktrees. Four of those checkouts had live CWD clients
  at audit time.
- Three provider branches remain on the public GitHub repository with no open
  PR.
- Recovery evidence from earlier passes (nine bundles covering ten refs, plus
  the PR #1711 bundle and ignored-data archive) is spread across about nine
  `~/.codex/task-artifacts/*` directories with no single index. The disk is 90%
  full.

## Solution Architecture

Every ref receives one of five dispositions:

| Disposition      | Meaning                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| `keep`           | Primary, protected, or out of scope. Untouched.                                                  |
| `hold`           | Bundle now as insurance, keep the ref, record owner label and review date.                       |
| `archive-delete` | Bundle, verify restore, owner approves the batch, delete the ref with the local delete mechanic. |
| `release-delete` | Merged checkout: owner releases the session, checkout removed, then archive-delete.              |
| `remote-delete`  | Provider branch: bundle, policy gate, named owner approval, leased push delete.                  |

**Removal gate (replaces "integration proof only" for dormant branches).** A ref
may be deleted only when all of the following hold:

1. Its exact tip, plus every reflog-only commit not reachable from that tip, is
   inside a bundle under the archive root.
2. The bundle's SHA-256 is recorded, `git bundle verify` passes, and a restore
   into a scratch location reproduces the exact tip and every reflog-only
   commit, and passes `git fsck --full`. The restore test runs the exact command
   text written to `RECOVERY.md` for that entry.
3. The ref's tip at deletion time equals the bundled SHA, using full
   40-character SHAs taken from `inventory-before.json` (enforced by the delete
   mechanic below).
4. No worktree has the ref checked out at deletion time. A SHA check cannot
   detect a checkout that keeps the same tip, so the delete mechanic enforces
   this separately. During each deletion window the owner keeps every other
   Claude and Codex session on this repository idle, so no checkout switch
   happens between the final checks and the deletion.
5. The owner approved that specific batch in chat after seeing the batch table.

**Bundle ref layout.** A bundle can only carry refs that exist in the source
repository. Each branch is bundled under its real `refs/heads/<name>`. Temporary
refs under `refs/archive-tmp/` are created only for reflog-only SHAs
(`refs/archive-tmp/<name>/reflog-<n>`) and for detached worktree HEADs
(`refs/archive-tmp/detached-<sha>`). They are deleted right after bundling, and
the inventory diff confirms none remain. Provider branches without a local
branch (Phase 4) are bundled from their tracking refs, so their entries
advertise `refs/remotes/origin/<name>`, not `refs/heads/<name>`. For every
entry, `dispositions.tsv` records the advertised ref exactly as
`git bundle list-heads` prints it, and `RECOVERY.md` restores with
`git fetch <bundle> <advertised-ref>:refs/heads/<name>` (or the scratch-clone
form if the pilot found prerequisites).

**Local delete mechanic.** Most "merged" branches were squash-merged, so
`git branch -d` refuses them. Every local deletion runs this sequence:

1. Precheck: `git rev-parse refs/heads/<name>` equals the bundled SHA, and
   `git worktree list --porcelain` shows no worktree on the branch.
2. `git -c core.abbrev=40 branch -D <name>`. Git refuses this deletion if any
   worktree has the branch checked out, and it checks in the same process that
   deletes the ref, which closes the gap left by a separate scan.
3. The printed `(was <sha>)` must equal the bundled SHA. If it differs, the tip
   moved after the precheck: immediately recreate the ref at the printed SHA
   with `git update-ref refs/heads/<name> <printed-sha> ""` and drop it from the
   run.
4. Post-scan `git worktree list --porcelain`. If any worktree now names the
   deleted branch, immediately recreate it at the bundled SHA with
   `git update-ref refs/heads/<name> <bundled-sha> ""`, drop it from the run,
   and report it.

**Remote delete mechanic.** Every remote deletion uses
`git push --force-with-lease=refs/heads/<name>:<sha> origin --delete <name>`,
which fails closed if the provider tip moved after bundling.

**Archive root.** `~/code/.agent-state-backup/branch-archive-2026-11-18/`,
beside the existing `branch-worktree-prune-2026-11-12/` record. It holds
per-batch bundles, raw reflog files, branch config sections, worktree data
archives, `inventory-before.json`, `inventory-after.json`, `dispositions.tsv`,
and one `RECOVERY.md` index. The index also lists the prior recovery evidence
(path, SHA-256, covered refs) in place; prior files are not moved. Absolute
paths and detail on security-related branches stay in that off-repo index, not
in this public plan.

**Authorization model.** Approving this plan authorizes no deletion. The pilot,
each local batch, each checkout release, and the remote deletions each need
their own in-chat owner approval at execution time.

### 3. Merged checkouts: release, remove, archive-delete

Per checkout, in this order, skipping any the owner does not release:

1. Save needed staged, unstaged, untracked, and selected ignored data (exclude
   `node_modules`, build outputs) into the archive root **before** any app
   action; record sensitive paths by name only. Claude Desktop can discard a
   checkout on archive. Record content fingerprints at save time: SHA-256 of
   `git diff --binary` and `git diff --cached --binary`, and per-file SHA-256
   (or symlink target) of every saved untracked and ignored entry. Record the
   untracked and recursive ignored file listings with the exclusion list defined
   in step 4.
2. Archive the branch **before** any app action, because app archival may delete
   the ref. Bundle the tip under its real ref, every branch-reflog SHA and every
   checkout HEAD-reflog SHA not reachable from that tip, a surviving ref, or an
   existing bundle (temp refs as above). Copy the branch reflog, the checkout's
   HEAD reflog file, and `branch.<name>.*` config. Verify and restore-test
   exactly as in Phase 2. Removing a checkout drops its HEAD reflog, which is
   the only record for the two detached checkouts.
3. Owner releases the owning session in its app.
4. Recheck immediately before removal: registration, HEAD, the untracked path
   set (`git status --porcelain=v1 -uall`) and recursive ignored file set
   (`git ls-files --others --ignored --exclude-standard`, without `--directory`,
   which would collapse a directory and hide additions inside it) equal to the
   step 1 listings. Both listings filter out the same explicit exclusion list,
   limited to regenerable dependency and build output (`node_modules/`, `dist/`,
   tool caches), recorded in the index and applied identically at backup and
   recheck. Every content fingerprint from step 1 is recomputed and equal to the
   saved values, plus zero CWD clients (`lsof +D` scoped to the path). Any
   added, removed, or changed path or fingerprint stops removal; save the new
   state, re-fingerprint, and re-ask the owner before continuing.
5. Remove through the owning tool:
   - Codex-managed checkouts: the owner runs Codex's archive flow in the Codex
     app; this session only verifies afterwards (registration gone, ref state
     recorded). If that flow already removed the branch ref, record that and
     skip the delete instead of failing it.
   - `.claude/worktrees/*`: the Claude app's worktree cleanup.
   - Unmanaged checkouts: `git worktree remove <path>` (never `--force`).

## Technical Considerations

- **Pattern usage**: follows the `worktree-storage-cleanup` skill (inventory,
  keep unknowns, archive before removal, owner-tool removal, no force) and the
  restore-validated bundle recipe from the 2026-11-17 runs. AGENT-SAFETY.md
  branch rules apply: no `reset --hard`, no `git add -A`, fetch before
  comparing.
- **Governing policy precedence**: provider and branch mutations need separate,
  action-scoped owner authorization. The owner chose agent-run remote deletion;
  this plan keeps that choice but adds the policy's Neon gate and named
  approval, which take precedence where they conflict.
- **Shallow repository**: bundle form and size are decided once in the pilot and
  reused.
- **Concurrency**: other Claude and Codex sessions share this repository and can
  move refs or switch worktree branches mid-run. The owner keeps those sessions
  idle during each deletion window. `git branch -D` refuses a branch checked out
  in any worktree at the moment of deletion; the `(was <sha>)` check catches a
  moved tip; the post-delete worktree scan catches a checkout switch that
  slipped past both, and the ref is recreated at once from a SHA whose objects
  are still present. Content fingerprints catch edits inside a checkout after
  backup. Any failure removes that ref or checkout from the run.
- **No gc**: objects of deleted refs remain until Git's own expiry; recovery
  relies on bundles, not on dangling objects.
- **Edge cases**: a declined release skips that checkout and its ref; a ref that
  drifted since baseline is skipped and reclassified; new refs created during
  the run are reported, not touched; Codex turn-diff refs are excluded from
  every comparison.
- **Public repository**: this plan names branches and SHAs only. Paths under the
  user's home, sensitive file names, and security-branch detail stay in the
  off-repo index.
- **Workflow**: no file edits or tests are involved beyond the router index
  regeneration, so no Hermes dispatch is required. Git operations run in this
  session with the approvals above.
