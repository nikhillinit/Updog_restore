# Production Release of the F_1.18.0 Schema Route Plan

**Governing policy:**
`docs/governance/solo-internal-change-and-production-policy.md` (resolve from
`origin/main`). This plan grants no merge, production, or release authority.
Merge, the baseline capture, and each release dispatch remain separate owner
actions.

Reviewed checkout: `origin/main` at `7ee0210fa` on 2026-09-29. The repository is
public: this plan cites only pushed SHAs, repository paths, and GitHub Actions
run and artifact identifiers. It contains no provider identifiers, hosts,
credentials, or account names.

Parent: F_1.18.0 (journaled schema apply route 0050-0061, ADR-103). This plan
releases the code that the F_1.18.0 route prepared the production schema for.

## Overview

Production runs `068430726` (last successful `release-production`, 2026-07-30).
`main` has moved 209 commits since then, including worker code, so the release
must use the two-phase route in `docs/workflows/PRODUCTION_SCRIPTS.md` ("Railway
worker deploy stage").

A primary release needs `baseline_evidence_b64` from a
`capture-release-baseline.yml` run. That run binds a planned PR, its frozen
head, and an approved plan file, and it refuses unless live `main` still equals
the pre-merge SHA. The PRs up to #1601 merged without a baseline capture, so
`7ee0210fa` cannot be released in primary mode.

This plan is the approved plan file for a release-vehicle PR. The PR changes
only this plan and one `CHANGELOG.md` note. The owner captures the baseline
against the PR's frozen head before merge, then releases the PR's merge commit.

## Release sequence

Each numbered step is a separate owner action. On any refusal, stop and re-plan;
never re-run a failed release attempt (`GITHUB_RUN_ATTEMPT` must be 1).

1. Prerequisite: add the `Production` environment secret
   `PRODUCTION_RELEASE_PROOF_GITHUB_TOKEN` (read-only access to this
   repository's Actions, checks, contents, pull requests, and branch
   protection). `release-proof.yml` requires it.
2. Freeze this PR's head once `CI Gate Status` is green. Any later push
   invalidates the baseline.
3. Dispatch `capture-release-baseline.yml` on `main` with
   `baseline_main_sha=7ee0210faeeb8074c53bfb821b2dd49c899b55be`, the frozen PR
   head, this PR's number, `plan_path` equal to this file's path, and
   `plan_sha256` equal to this file's SHA-256 at the frozen head. `main` must
   not move between this step and the merge.
4. Merge this PR (squash). The merge commit becomes the release SHA. Wait for
   `CI Gate Status` success on it.
5. Phase A: dispatch `release-production.yml` with `mode=railway-workers-only`,
   `release_mode=primary`, `expected_sha` equal to the merge commit, `pr_number`
   equal to this PR's number, the baseline binding from step 3, and the schema
   apply identity from "Completed before this plan" (`schema_precursor_sha` is
   `7ee0210faeeb8074c53bfb821b2dd49c899b55be`). `scripts/deploy-production.ps1`
   builds both base64 inputs.
6. Capture the ADR-082 operator evidence from both workers' `/health` and
   `/ready` endpoints and encode it with
   `node scripts/release/operator-evidence-bundle.mjs encode`. G4 accepts probes
   at most 120 minutes old and within 15 minutes of each other, so capture them
   immediately before step 7.
7. Phase B: dispatch `release-production.yml` with `mode=full` and the same
   inputs plus `operator_evidence_b64`.
8. Read `/api/version` and confirm the promoted SHA equals the merge commit.
   Then lift the ADR-103 migration freeze.

## Constraints

- ADR-103 freeze stays in force until step 8: no merge that touches
  `migrations/` or `scripts/prod-schema-manifests/`.
- No other merge between step 3 and step 7. A new `main` head fails the phase B
  re-fence and restarts the sequence at a new baseline.
- The release-vehicle PR changes no runtime code, so it needs no Phoenix truth
  run and no test changes.
