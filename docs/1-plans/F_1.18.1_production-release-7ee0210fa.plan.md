# Production Release of the F_1.18.0 Schema Route Plan

**Governing policy:**
`docs/governance/solo-internal-change-and-production-policy.md` (resolve from
`origin/main`). This plan grants no merge, production, or release authority.
Merge, the baseline capture, and each release dispatch remain separate owner
actions.

Reviewed checkout: `origin/main` at `45228c19c` on 2026-09-30. The repository is
public: this plan cites only pushed SHAs, repository paths, and GitHub Actions
run and artifact identifiers. It contains no provider identifiers, hosts,
credentials, or account names.

Parent: F_1.18.0 (journaled schema apply route 0050-0061, ADR-103). This plan
releases the code that the F_1.18.0 route prepared the production schema for.
The file name keeps `7ee0210fa`, the commit the schema apply ran at.

## Overview

Production runs `068430726` (last successful `release-production`, 2026-07-30).
`main` has moved more than 200 commits since then, including worker code, so the
release must use the two-phase route in `docs/workflows/PRODUCTION_SCRIPTS.md`
("Railway worker deploy stage").

A primary release needs `baseline_evidence_b64` from a
`capture-release-baseline.yml` run. That run binds a planned PR, its frozen
head, and an approved plan file, and it refuses unless live `main` still equals
the pre-merge SHA. The PRs up to #1605 merged without a consumable baseline, so
`45228c19c` cannot be released in primary mode. #1602 merged before its capture
ran; the #1604 and #1605 phase A runs failed before any provider mutation (items
7 and 8 below).

This plan is the approved plan file for a release-vehicle PR. The PR changes
this plan, one `CHANGELOG.md` note, the release-proof call in
`release-production.yml` with its regression test, and two production dependency
patch bumps (`brace-expansion` 5.0.12, `engine.io` 6.6.11). The owner captures
the baseline against the PR's frozen head before merge, then releases the PR's
merge commit.

## Release sequence

Each numbered step is a separate owner action. On any refusal, stop and re-plan;
never re-run a failed release attempt (`GITHUB_RUN_ATTEMPT` must be 1).

1. Prerequisite, done: the `Production` environment holds the secret
   `PRODUCTION_RELEASE_PROOF_GITHUB_TOKEN` with read access to this repository's
   Administration (branch protection), Actions, and Contents. Check runs are
   public. `release-proof.yml` requires it.
2. Freeze this PR's head once `CI Gate Status` is green. Any later push
   invalidates the baseline. The PR stays in draft until step 3 succeeds, so it
   cannot merge early.
3. Dispatch `capture-release-baseline.yml` on `main` with
   `baseline_main_sha=45228c19c59352eb89541397a0b83517e003fad3`, the frozen PR
   head, this PR's number, `plan_path` equal to this file's path, and
   `plan_sha256` equal to this file's SHA-256 at the frozen head. The workflow
   refuses unless its own commit, live `main`, and this SHA are equal. If `main`
   moves before the capture, update this SHA, re-freeze, and recompute
   `plan_sha256`. `main` must not move between this step and the merge.
4. Only after step 3 succeeds, merge this PR (squash). The merge commit becomes
   the release SHA. Wait for `CI Gate Status` success on it. Then dispatch full
   CI on `main` at the merge commit: `ci-unified.yml` with `run_full_suite=true`
   and `enable_security=true`, and `testcontainers-ci.yml`. G3 requires every
   locked context in `scripts/release/verify-exact-sha-checks.mjs` to succeed on
   the exact release SHA, and a push run skips path-filtered lanes. Wait for
   both runs to succeed, then replay the G3 aggregate step read-only.
5. Phase A: dispatch `release-production.yml` with `mode=railway-workers-only`,
   `release_mode=primary`, `expected_sha` equal to the merge commit, `pr_number`
   equal to this PR's number, the baseline binding from step 3, and the schema
   apply identity from "Completed before this plan" (`schema_precursor_sha` is
   `7ee0210faeeb8074c53bfb821b2dd49c899b55be`, the schema apply commit, not the
   baseline). `scripts/deploy-production.ps1` builds both base64 inputs. Before
   dispatch, replay the preflight checks read-only in a fresh clone of the
   release commit with full history, matching the workflow checkout
   (`fetch-depth: 0`), not in a development worktree.
6. Capture the ADR-082 operator evidence from both workers' `/health` and
   `/ready` endpoints and encode it with
   `node scripts/release/operator-evidence-bundle.mjs encode`. G4 accepts probes
   at most 120 minutes old and within 15 minutes of each other, so capture them
   immediately before step 7.
7. Phase B: dispatch `release-production.yml` with `mode=full` and the same
   inputs plus `operator_evidence_b64`.
8. Confirm the step 7 run concluded `success` on attempt 1, including
   `post-promotion-smoke` and `evidence-finalizer`, and uploaded the release
   evidence manifest. `/api/version` changes at promotion, before those jobs
   finish, so a matching version alone is not proof. Then read `/api/version`
   and confirm the promoted SHA equals the merge commit. Only then lift the
   ADR-103 migration freeze.

If phase B promotes and a later job fails, production already runs the merge
commit. Keep the freeze on and stop; the owner chooses between a rollback-mode
release and a forward fix.

## Open risk

The staged-candidate alias checks (`verifyStagedVercel`,
`release-production.yml` `validate-deployment`) still read the deployment's
creation-time alias field, which #1603 left unchanged. If phase B fails there,
it fails before promotion, and that run's evidence drives the fix.

`Protected Boot Proof`, `G3 Exact-SHA Verdict`, and the provider identity proofs
have never run live with credentials. Expect first-use defects there too; each
fails before any provider mutation in phase A. A read-only replay of the G3
aggregate step on `45228c19c` already found one: three locked `ci-unified.yml`
lanes were skipped and `Testcontainers` never ran, so step 4 now dispatches full
CI. A full-CI rehearsal on `45228c19c` (run 36681735283) then failed
`Dependency Validation (Linux)` on high-severity `npm audit` findings in
`brace-expansion` 5.0.9 and `engine.io` 6.6.9; this PR bumps both. The owner
approved these two bumps despite the dependency hold, because the release cannot
pass G3 without them.

## Constraints

- ADR-103 freeze stays in force until step 8 completes: no merge that touches
  `migrations/` or `scripts/prod-schema-manifests/`.
- No other merge between step 3 and step 7. A new `main` head fails the phase B
  re-fence and restarts the sequence at a new baseline.
- The release-vehicle PR changes no calculation code, so it needs no Phoenix
  truth run. It changes one release workflow line, one regression test, and two
  transitive production dependency patch versions.
