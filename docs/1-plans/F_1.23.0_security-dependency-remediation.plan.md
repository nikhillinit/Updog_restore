## Problem Statement

- Protected main carries four HIGH Trivy findings duplicated across the
  filesystem and container scans: `body-parser` 2.3.0 (CVE-2026-111181,
  GHSA-27r3-jxmh-p828), `follow-redirects` 1.16.0 (CVE-2026-111755,
  CVE-2026-111756), and `zod` 3.25.76 (CVE-2023-54404, GHSA-mrhx-c7xc-m3w5).
- The body-parser defect is an uncaught decoder exception: one valid compressed
  frame followed by trailing bytes crashes the process after the response is
  sent. Both surfaces parse JSON before authentication (`server/app.ts:161`,
  `server/server.ts:159-164`) with inflation enabled, so the input is reachable
  unauthenticated.
- Zod 3.25.76 parses every element of a bounded array before emitting the size
  issue. Zod 4.6.7 root rejects before element parsing. The `zod@4.6.7/v3`
  subpath keeps the old behavior, so a package bump whose imports resolve to
  `zod/v3` is scanner-green and behavior-red.
- The Zod surface is large: 290 production files import `zod` (287 from `'zod'`,
  3 from `'zod/v4'`), 104 lines read `ZodError.errors`, 50 call single-argument
  `z.record`, 163 call `.uuid()`, 372 reference `ZodIssueCode`, 760 lines call
  `.default(` (470 in Zod-importing files, 327 in Drizzle-importing files, 39 in
  files importing both), and 108 test files assert on Zod message text. Tests
  contain 89 fixture ids that are not RFC 9562 UUIDs (nil-style
  `00000000-0000-0000-0000-000000000001`).
- `CI Gate Status` fail-closes on `pr-light-security`, whose Trivy filesystem
  scan runs with `exit-code: '1'` for any change matching the `pr_security`
  filter (`package.json`, `package-lock.json`, `server/**`, `shared/**`). A
  body-parser-only pull request therefore cannot go green while Zod 3 remains.
- The ADR-110 helper (`credential_repair.py`, SHA-256
  `e4a2a58f32767288d863faf821d169938ce7c50542f5b0cb7f062d2fb71bae01`) verifies
  the post-create inventory by successor label only and the final inventory by
  label counts. Independent fake-provider tests reproduced three false
  verified-success outcomes: baseline identity change during create (then an
  avoidable secret write), baseline substitution after write, and an unrelated
  token addition after write.

## Solution Architecture

One pull request from refreshed protected main, two commits, no stacked branches
(a child squash swallows its parent on this repository):

1. **Commit 1 (W3):** `package.json` range change for `body-parser`, lock-only
   refresh of `follow-redirects`, parser compatibility and installed-resolution
   tests.
2. **Commit 2 (W4):** `zod` range change, unification of the three `zod/v4`
   imports to `'zod'`, compile-driven API fixes, behavior-preserving rename
   rules, a `zod/v3` import-ban test, the early-bound regression test bound to
   the production import, the liquidity `months` bound derived from the existing
   cashflow contract, and the classification table of unbounded route arrays.

Migration principle for commit 2: validation behavior is preserved everywhere
except four named intentional changes (section 3b). Where Zod 4 tightened a
default (`.default`, `.uuid`, enum-keyed `z.record`), the plan uses the Zod 4
API that reproduces Zod 3 behavior (`.prefault`, `.guid`, `z.partialRecord`).
Tightening is available later as a separate decision with its own fixture work.

Phase 0 (W1) is a copy-and-repair of the reviewed helper directory into a new
dated sibling directory. The reviewed 2026-10-21 directory is never edited. The
fixed action ledger and lock paths are intentionally unchanged, so the copy does
not replenish the action budget (the helper README states this property; it is
the desired one). The repair introduces one canonical identity helper over the
four fields the live provider already returns per token record (`name`,
`createdAt`, `projectId`, `environmentId`) and anchors every token inventory
attestation to the preflight inventory plus exactly one validated successor.

### 0. ADR-110 helper revision (Phase 0, out-of-tree)

**Files**: a new sibling directory of the reviewed helper directory, suffixed
with the revision date `20261027`, holding copies of `credential_repair.py`,
`test_credential_repair.py`, `README.md`, `ADMISSION.md`, `sealed_box.cjs`,
`test_sealed_box.cjs`, and `test-evidence.json`. Exclude `__pycache__`. The
2026-10-21 directory stays byte-identical.

**Current state**: `Orchestrator.apply` captures the complete token inventory in
`_preflight` (`preflight["tokens"]`, around line 555-573) and compares the raw
list before create (around line 732). After `create_token` and
`validate_exact_token` it reads `tokens_after_create` and checks only that
exactly one record carries the successor label with the right scope (around line
754-757). Before the write it requires
`tokens_before_write == tokens_after_create` (around line 775). After the write
it counts baseline, failed-attempt, and successor labels (around line 811-816)
and records `original_token_preserved=True`. The unknown-outcome paths
(`_reconcile_existing`, around line 678-682, and `_finish_unknown_create`,
around line 855-859) look the successor up by label to identify a token whose
value was lost; that is identification, not attestation, and stays label-based.

**Modifications** (`credential_repair.py`, new copy only):

- Add a module-level helper beside `metadata_map` that canonicalizes a token
  inventory: build the identity tuple
  `(name, createdAt, projectId, environmentId)` per record, raise
  `RepairError("TOKEN_INVENTORY_INVALID")` on a missing or non-string field or a
  duplicate identity, and return the sorted tuple of identities
  (order-insensitive). Do not assume a provider token ID; the live provider's
  GraphQL selection exposes only these four fields.
- Route every token inventory attestation through that helper: the
  recovery-sample comparison in `_preflight`, the pre-create comparison, the
  post-create check, the pre-write check, and the final check. An order-only
  permutation is no longer drift; duplicates and incomplete pagination still
  fail closed.
- Post-create: compute `expected_tokens` as the canonical preflight inventory
  plus exactly one new identity. Require the canonical post-create inventory to
  have length `len(preflight) + 1` and to contain every preflight identity;
  otherwise raise `RepairError("TOKEN_INVENTORY_CHANGED_DURING_CREATE")` before
  `SECRET_WRITE_ATTEMPTED` (terminal `STOPPED`, created token retained, receipt
  preserved). The single new identity must carry the successor label and the
  validated project and environment; otherwise keep the existing
  `CREATED_TOKEN_METADATA_MISMATCH`.
- Pre-write: compare the canonical inventory to `expected_tokens`; keep the
  existing `TOKEN_METADATA_CHANGED_BEFORE_WRITE` code.
- Final: replace the label-count block with canonical equality against
  `expected_tokens`; keep the `FINAL_TOKEN_INVENTORY_MISMATCH` code. Because
  `secret_write_attempted` is already set, the existing terminal logic yields
  `PARTIAL_OR_UNKNOWN` with no retry, rewrite, revoke, or rollback.
- Keep scope revalidation, source and binding rechecks, secret-metadata checks,
  quiescence checks, durable phase markers, deadlines, and the no-retry behavior
  unchanged. `original_token_preserved=True` stays as a receipt field and is now
  backed by the equality check.

**Modifications** (`test_credential_repair.py`, new copy): add regressions using
the existing `token_inventory` monkeypatch pattern from
`test_stale_secret_metadata_after_create_never_writes`, not new provider flags:

- baseline `createdAt` changes once `create_count` is set and before any write:
  expect `TOKEN_INVENTORY_CHANGED_DURING_CREATE`, `write_count == 0`,
  `create_count == 1`, no `revoke` call;
- baseline `createdAt` changes after `write_count` is set: expect
  `PARTIAL_OR_UNKNOWN`, counts `(1, 1)`, no `revoke`;
- an unrelated record appears after the write: `PARTIAL_OR_UNKNOWN`;
- a pre-existing unrelated record (added to the fake inventory before `apply`)
  disappears during create: stop before write;
- successor label or scope drift after create: existing
  `CREATED_TOKEN_METADATA_MISMATCH`, `write_count == 0`;
- order-only permutation of a two-record inventory after create and after write:
  `CREDENTIAL_REPAIR_VERIFIED` with counts `(1, 1)`;
- duplicate baseline record at preflight: `TOKEN_INVENTORY_INVALID`, zero
  mutations.

All 32 existing tests must still pass. Regenerate `test-evidence.json` with the
new file digests and test count; the two sealed-box dependency tree digests it
records are computed from an installed repository checkout, so reverifying them
needs `npm ci` first. Add a revision note to the copied `README.md`. Record the
new `credential_repair.py` SHA-256 in private operator evidence; any admission

### 4. Type-scoped `.default` to `.prefault` rename (Phase 2, commit 2)

Zod 4 `.default()` short-circuits: when input is `undefined` it returns the
default value without parsing it, and the value must match the output type. Zod
3 parsed the default through the schema. `.prefault()` is Zod 4's pre-parse
default and reproduces Zod 3 semantics exactly.

**Rule**: rename `.default(` to `.prefault(` on every Zod receiver in production
code. Do not rename Drizzle column builders, which also use `.default(` and have
no `.prefault`.

- Census at the reviewed checkout: 760 `.default(` lines; 470 in files that
  import `zod`; 327 in files that import `drizzle-orm`; 39 in the 8 files that
  import both (`shared/schema/shares.ts` 12, `server/routes/cohort-analysis.ts`
  7, `server/routes/timeline.ts` 6, `shared/schema/user.ts` 3,
  `server/routes/shares.ts` 3, `server/routes/lp-notifications.ts` 2,
  `server/routes/lp-documents.ts` 2,
  `server/services/investment-ledger/ledger-correction-service.ts` 1). Those 39
  lines are disambiguated by receiver, line by line.
- Over-rename detection: `npm run check` fails on a Drizzle builder with
  `.prefault`.
- Under-rename detection: after the rename, grep Zod-importing production files
  for remaining `.default(` and justify each remaining line in the commit
  message (expected: Drizzle receivers only).
- New code written after this plan may use `.default()` deliberately where
  short-circuit semantics are wanted.

**Defaults under `.partial()` and `.optional()`.** Zod 4 applies a field's
default even when the field is optional, so `Create.partial()` now fills omitted
keys with the create-time defaults; Zod 3 left them absent, and `.prefault` does
not restore that. A name-only update through `UpdateDealSchema`
(`server/services/deal-pipeline/schemas.ts:52`, defaults `status: 'lead'` and
`priority: 'medium'` at lines 38-39) would reach the persisting service
(`server/services/deal-pipeline-service.ts:190`) with both fields set.
`ConstraintsSchema.partial()` (`shared/schemas.ts:75`) is relied on to suppress
the `maxPerCompany` default
(`shared/core/reserves/constrained-reserve-substrate-adapter.ts:45, 89`).

Rule: a `.partial()` schema never inherits defaults. For each of the 11
`.partial()` sites (`server/routes/portfolio-intelligence.ts:98`,
`server/routes/cashflow.ts:71`, `server/routes/liquidity.ts:62, 81`,
`server/services/deal-pipeline/schemas.ts:52`, `shared/schemas.ts:75`,
`shared/contracts/fund-scenario-sets-v1.contract.ts:72`,
`shared/schemas/portfolio-optimization.ts:50, 242`; 7 of these files also
contain `.default(`), split the object into a default-free base, a create schema
that adds `.prefault` fields, and a partial schema derived from the base. Where
no field of the partialized object carries a default, record that and leave it.
Same-line `.default(...).optional()` chains: none in production; grep the
multi-line form during the rename. Regressions: a name-only deal update parses
to an object without `status` or `priority` keys; `ConstraintsSchema` partial
parse of `{}` has no `maxPerCompany` key.

## Technical Considerations

- **Pattern usage**: common-route manifest, impl map, and group slices are
  untouched; no new route, migration, flag, or worker. Idempotency, optimistic
  locking, cursor validation, and queue timeouts are unaffected.
- **Gate coupling**: the Trivy filesystem scan in `pr-light-security` and the
  separate `security-scan.yml` both run on this pull request and must report
  none of the four findings on the final composed candidate. Separately green
  fragments do not count. `.trivyignore` is not edited.
- **Empty worktree installs**: managed worktrees ship without `node_modules`;
  run `npm ci` before any repository check, and before the red parser run.
- **Preact production bundle**: `npm run build:web` is where client-only Zod
  breakage surfaces; `dev:client` runs React and can pass while the bundle
  fails. Run it before pushing.
- **Tests are not typechecked**: compile catches production `.errors`,
  `z.record`, `.ip()`, `.deepPartial()`, and `ZodTypeDef` breaks; the 27
  Zod-importing test files and 108 message-text assertions need a grep pass. New
  and updated assertions use `code` and `path`, not message strings.
- **Mixed-version instances**: after the bump only one Zod runtime exists.
  Before the bump the repository already mixes `zod` (v3) and `zod/v4`; the
  three unified imports remove that.
- **Semantic-change inventory**: section 3b is the complete list of intended
  validation-behavior changes; everything else is meant to be
  behavior-preserving or wire-shape only. A reviewer finding a fifth change
  during implementation adds it to ADR-111 or reverts it.
- **Public repository**: the plan, commits, and tests carry no helper path,
  provider identifier, or account name. The helper digest alone is tracked.
- **Edge cases**: `.prefault` on a `.transform` chain parses the default (Zod 3
  behavior); `.default` on the same chain would return the raw default (Zod 4
  behavior). Nested object defaults with inner defaults (89 literal object or
  array defaults) behave as before only under `.prefault`. `z.coerce` input type
  `unknown` can widen inferred request input types; the 13 `z.input<` files are
  checked. `.nonempty()` losing its tuple type can surface
  `noUncheckedIndexedAccess` errors at index-zero reads. Enum-keyed records with
  `.default({})` reject their own default unless converted to `z.partialRecord`.
  Defaults inside optional fields apply in Zod 4, so `.partial()` injects them;
  `.prefault` does not change that (section 4).
