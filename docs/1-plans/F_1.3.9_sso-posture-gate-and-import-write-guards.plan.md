# F_1.3.9 SSO Posture Gate and Import Write Guards Implementation Plan

## Overview

One pull request, cut from an inspected `origin/main`, that does four things:

1. Keeps the release workflow working now that Vercel Authentication covers
   every deployment of the production project.
2. Adds a fail-closed release check that production stays behind Vercel
   Authentication.
3. Records the one-time protection change as a deviation, with a hold on access
   expansion.
4. Applies the ADR-079 team write-role guard pattern to ten import and
   reconciliation write routes in `server/routes/lp-reporting/imports.ts`.

## Problem Statement

- **The production project domain was not covered.** On 2026-11-20, during
  owner-authorized verification work, an agent session found that the project's
  Vercel Authentication mode (`all_except_custom_domains`) did not cover the
  project's production domain.
  - On the owner's explicit instruction, the session changed the mode to `all`.
    It used the Vercel API with the owner's CLI credentials, after the MCP
    connector refused the write (403).
  - No admitted route covered that provider action, so the governing policy's
    production-action rule requires a recorded deviation (ADR-112/ADR-113
    precedent). Later admission cannot authorize it retroactively.
- **The next release would fail.** Under `all`, the post-promotion smoke in
  `.github/workflows/release-production.yml` (job `post-promotion-smoke` ~1849,
  step "Run authenticated production smoke" ~1868-1885) fails, because it passes
  no `VERCEL_AUTOMATION_BYPASS_SECRET`. The Playwright `production` project
  (`playwright.config.ts:150-162`) sends the bypass header only when that
  variable is set.
  - Every other production HTTP step in the workflow already passes the secret:
    staged smoke ~993-1075, `staged-provider-identity` ~1325,
    `g4-operator-evidence` ~1419, `promote` ~1636.
- **Nothing stops the mode from regressing.** The provider evidence collector
  records the deployment, its aliases and the version, not the project's
  protection posture.
- **Import write routes adopt the ADR-079 pattern.** ADR-079 rule 2 puts
  ordinary data-entry writes behind `TEAM_WRITE_ROLES`, with
  `enforceProvidedFundScope(..., { forWrite: true })` on write paths. This plan
  applies that guard to the LP-reporting import and reconciliation write routes
  listed in section 5.

## Solution Architecture

- **Release workflow:** add the existing bypass secret, with its
  required-variable guard, to the post-promotion smoke step.
- **Posture gate, keeping collect and verify separate (existing pattern):**
  - `collect-provider-evidence.mjs` gains an opt-in flag. With it, the collector
    writes an access-posture record:
    - the project's protection fields and bypass-entry count and scopes, never
      secret values;
    - the hostname inventory, as the project domains ∪ the canonical production
      deployment's aliases;
    - one unauthenticated probe per hostname.
  - `verify-provider-identity.mjs` gains an optional input that fails closed
    unless the mode is `all` and every inventory hostname has exactly one probe
    that is an SSO redirect or a 401.
  - `release-production.yml` passes both flags in two places, so the posture is
    checked at the final promotion decision and not only before approval:
    - `staged-provider-identity`;
    - the `promote` job's "Collect and verify fresh provider evidence before
      promotion" step (~1627, `--mode operator`), which runs after the approval
      wait.
  - `promote` needs `staged-provider-identity`, and that job runs only on
    attempt 1, so a re-run cannot skip the gate.
  - `release-proof.yml` does not pass the flag, so its behavior is unchanged.
- **Governance record, minimal public disclosure:**
  - ADR-117 records:
    - the deviation;
    - the standing rule that the production mode stays `all`;
    - the hold on access expansion until the ADR-079 write-guard review of
      Vercel-reachable writes is closed and its fixes are in production.
  - A policy section and `docs/workflows/PRODUCTION_SCRIPTS.md` sections mirror
    it. No exposure narrative, probe output or account history goes in the
    public repository.
- **Route guard:**
  - Each of the ten route registrations carries the `18284e10f` chain inline:
    - `requireWriteRole(TEAM_WRITE_ROLES)`;
    - an async step that parses the fund ID (400 on missing or invalid);
    - `enforceProvidedFundScope(req, res, fundId, { forWrite: true })`;
    - `enforceTeamWriteRole(req, res)`.
  - Inline, not a shared array: the matrix seeder derives role and fund-scope
    evidence only from text inside each registration
    (`audit/surface-contract-matrix/scripts/seed-matrix.mjs:474-531`). The
    actuals routes, which use a spread array, show the result: empty
    `auth_roles`.
  - A module-local helper may hold the fund-ID parse, as long as the three guard
    calls stay literal in each registration.
- **Matrix:**
  - One reseed, then a scoped review covering the 24 rows bound to `imports.ts`
    and every row the reseed demotes. Owner approval goes through
    `approve-matrix.mjs`.
  - README rule: a scoped review of a write row records its effective write
    guard, an equivalent control (such as the actuals pilot grant), or an
    explicit exception.
- **Rollout gate:** an owner step before the release that carries this change.
  It is a read-only census of active production users by role, and the release
  stops if any active user's role is outside `admin`, `partner` or `analyst`.
  LP-linked identities need no census row: `enforceTeamWriteRole` denies them
  whatever their role. Results stay out of the repository.

### 2. Opt-in access-posture collection

**File**: `scripts/release/collect-provider-evidence.mjs`

**Current state**: collects `/v13/deployments/{host}`, the deployment aliases,
`/api/version` (with bypass) and Railway topology. Writes `vercel-evidence.json`
and `railway-evidence.json`. Takes `--deployment-url` and `--output-dir`.

**Modifications**:

- New opt-in argument (for example `--access-posture`). It requires
  `VERCEL_PRODUCTION_HOSTNAME`, which is already set in
  `staged-provider-identity`. Without the flag, behavior and outputs are
  byte-identical to today.
- With the flag, add bounded reads under the existing deadline and `getJson`
  transport:
  - `/v9/projects/{projectId}?teamId=`;
  - `/v9/projects/{projectId}/domains?teamId=`;
  - the canonical production deployment (`/v13/deployments/{canonical host}`)
    and its aliases.
- Extract only these fields:
  - `ssoProtection.deploymentType`;
  - `passwordProtection` and `trustedIps`, as enabled flag and type;
  - the `protectionBypass` entry count and `scope` values. Bypass keys are the
    secrets and are never read into the output.
- Inventory: domain names ∪ canonical deployment aliases, deduplicated and
  sorted.
- Probe each hostname with `GET /api/health`: redirect `manual`, no bypass
  header, no cookie, same deadline. Record the status and the redirect target's
  host and path prefix only.
- Write `vercel-access-posture.json` through `writeEvidence`, which applies the
  no-secret assertion. The collector makes no pass/fail decision.

### 3. Access-posture verification

**File**: `scripts/release/verify-provider-identity.mjs`

**Modifications**:

- New optional argument naming the posture file. When present, fail closed
  (nonzero, generic message) unless:
  - `deploymentType === 'all'`;
  - the inventory is non-empty, has no duplicates, and contains the canonical
    hostname;
  - the probe set maps one-to-one onto the inventory: exactly one probe per
    hostname, none missing, no duplicate, no probe for a hostname outside the
    inventory;
  - every probe is a 401, or a 3xx to host `vercel.com` with path prefix
    `/sso-api`.
- A missing or malformed file fails closed.
- Password and trusted-IP fields are recorded but not asserted. The probes are
  the ground truth.
- Absent the argument, behavior is unchanged.

## Technical Considerations

- **Pattern usage**: the collect/verify split mirrors provider identity. The
  guard chain matches `18284e10f` and the ADR-079 Phase 1 routes.
- **Secret hygiene**: the posture record holds no bypass key, token or cookie.
  Tests assert this through `assertNoSecret`.
- **Probe semantics**: Vercel answers unauthenticated protected requests with a
  302 to `vercel.com/sso-api`. Accept 401 too. Any 2xx, a 4xx other than 401,
  any 5xx, or another redirect is a failure.
- **Token scope**: the release `VERCEL_TOKEN` must read project settings and
  domains. If it cannot, the gate fails closed and the owner widens the token
  scope.
- **No pre-release runtime proof**: releases are blocked on the 0062 chain, so
  the gate first runs at the next owner dispatch. Unit tests carry the logic.
- **Legacy alias trap**: `TEAM_WRITE_ROLES` admits the `viewer` and `operator`
  aliases, so `enforceTeamWriteRole` must accompany `requireWriteRole`.
- **Matrix churn**: a reseed can demote later-mounted rows, and the review must
  cover them.
- **Mock completeness**: suites that `vi.mock` auth modules must export
  `requireWriteRole`, `enforceProvidedFundScope` and `enforceTeamWriteRole`.
  Patch the test doubles; never widen production code.
- **Callers**: only client UI calls these routes:
  - `client/src/hooks/lp-reporting/useLedgerImport*`, `useValuationMarkImport*`
    and `useImportBatchReconciliation`;
  - the `client/src/pages/lp-reporting/` ledger and valuations pages;
  - `LedgerEventForm`, `LedgerTable`, `ValuationMarkForm` and
    `ValuationMarksTable`. No smoke, canary, script or server caller exists, so
    the release canary is unaffected.
- **Edge cases**:
  - admin always passes;
  - a partner or analyst without the fund grant is denied;
  - an invalid fund ID gets 400 before scope work;
  - a foreign `caseId` or `batchId` gets 404;
  - a bulk-resolve list naming a foreign case writes nothing to that case and
    returns a per-item 404, while same-fund items keep their per-item outcome;
  - a new custom domain is probed automatically.
