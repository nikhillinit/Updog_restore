## Problem Statement

Wave H capability is partially built but cannot ship as one batch:

- The context-rail view model exists (`context-rail-view-model.ts`) with a
  single consumer (`dashboard-modern.tsx`), but there is no view-preset code
  anywhere in the repo, and the shared rail contract from #1288 has no approved
  prototype. #1284 (prototype, human approval, non-shipping) gates #1288
  (implementation) — they must never be batched together.
- The decisions operating-object from ADR-067 (`DECISIONS.md:9628-9670`) has no
  schema, no evidence links, no routes, and no UI. The live #1289 issue body
  still lists only `accepted|rejected` while ADR-067's lifecycle is
  `proposed → accepted|rejected|deferred`; the issue body must be reconciled
  before dispatch.
- Task creation lacks idempotency; the retrofit shares #1289 with the schema
  work but is a separable deliverable.
- The activation soak target is unnamed (#1287), the deployed surface is
  un-audited (#1283), and representative-fund economics eligibility (ELIG) is
  undecided — all three gate downstream releases, and ELIG's probe must query
  the exact policy-pinned envelope, not the newest row.

## Solution Architecture

Three lanes with explicit blocking edges; each numbered item is its own TRIP-2
unit of work (no cross-item batching):

- **UI lane**: `#1284` (non-shipping prototype + HITL approval) → `#1288`
  (shared rail implementation) → `#1293` (operations page).
- **Decisions backend lane**: `#1289(a)` (migration 0050 + decisions schema +
  decision-sourced evidence links) and `#1289(b)` (task create-idempotency
  retrofit) → `#1290` (lifecycle + evidence-link routes) → `#1293` (operations
  page). #1289(a) and #1289(b) are independent of each other but both ship under
  issue #1289.
- **Audit lane**: `#1283` (read-only deployed-surface preflight; its
  facts-triggered shadow probe is blocked by NEW-A from the Phase 0 plan),
  `#1287` (HITL target naming), `ELIG` (live-DB eligibility probe; blocked by
  #1287 because the probe needs the named target).

Cross-release edges: #1283 evidence and the #1287 target feed `F_1.2.0`; ELIG's
promotion decision conditionally promotes #1320 (pre-#1296) and #1321 + #1337
into `F_1.3.0`, with the #1338 coordination decision recorded on the ELIG issue.

## Technical Considerations

- **No batching across gated items**: #1284 (prototype + human approval) is
  never batched with #1288; #1290 (routes) and #1293 (UI) are separate items
  with #1293 blocked by #1290. Each item above is a standalone TRIP-2 unit.
- **Issue-body drift**: the live #1289 body contradicts ADR-067's `deferred`
  lifecycle. Code must implement ADR-067; the body reconciliation is tracked as
  an (HITL — external) prerequisite, not an implementation task.
- **Migration safety**: drizzle 42830 (`unique()` vs `uniqueIndex` on FK
  targets) and journal-pin self-reference are the two known footguns for
  migration 0050; both are pinned as invariants on #1289(a).
- **Mount parity**: new routes 404 in production unless manifest, impl map, and
  both group slices are updated together; `npm run policy:verify` is the gate.
- **Pinned-envelope probe**: economics executes the envelope pinned by
  `internal_economics_policy_versions.capital_envelope_version_id`; probing the
  newest `created_at` row would promote on the wrong basis. The probe query
  above is the corrected form.
- **HITL bottlenecks on this release**: #1284 prototype approval, #1287 target
  naming, ELIG promotion decision. Three human gates; schedule accordingly.
- **Prompt-drift risk**: plan keyed to origin/main `a3d0a6b6`; re-fence before
  each dispatch.
