## Overview

Restore the release-critical merge sequence without weakening the signed G1/G3
surface contract or invalidating the frozen release candidate unnecessarily. PR
#1381 is the only immediate merge target. PR #1380 remains an independently
owned active lane and is consumed only through explicit readiness evidence.

Default sequence:

1. make two isolated approval tests use their isolated workspace as discovery
   root instead of scanning the full repository;
2. verify the deterministic test-only repair locally and through fresh CI;
3. correct PR metadata and merge #1381 as surface-matrix closure, not final G3;
4. hand off the separate Child F G4-readiness PR before any final source freeze;
5. establish a new frozen candidate after Child F, rerun G3 approval/proof, and
   complete G4 before allowing #1380 onto main;
6. rebase and verify #1380 after G4 without deploying it into the active soak.

This plan does not implement Child F, perform a production release, mutate a
provider, promote G4, activate G5, or implement work on PR #1380.

## Problem Statement

PR #1381 is blocked by one 60-second timeout in
`surface-contract-matrix-approve.test.ts` after 5,856 other tests passed. The
same code SHA, `9afa5115a228a371aa0aa1882003d1373f8b2c80`, previously completed
required CI successfully. The current head,
`5d6cfbddef8a20d2ac5579c1bc8d4d5a8b7792de`, differs from that passing SHA only
through seven planning/routing documents merged from main.

The root cause is a hermeticity defect in the test. Two isolated-workspace
approval calls still pass the real repository root, causing `loadState()` and
`validateCandidate()` to run repository-wide listener and auth-role discovery
through `git ls-files` and source reads. Four-worker full-suite contention can
push that unnecessary discovery beyond the test's existing 60-second budget. CI
reported no rollback assertion failure, leaked temporary file, or production
rollback error.

PR #1381's description also understates its cumulative scope. The PR contains
the planned G3 runtime, worker, release-proof, deployment-topology, test, audit,
and generated-artifact work. It changes `package-lock.json` root metadata even
though its exclusions say there are no lockfile changes. These metadata errors
do not require a source change but must be corrected before merge.

PR #1380 addresses the separate dependency-drift contract. It is actively owned
by the user in Codex task `019fed6c-8d62-7f40-a876-f0ca52692d6d`. Its current
review remains fix-first: validation must cover more than same-path
`resolved`/`integrity` changes. Editing, rebasing, pushing, or commenting on
that PR is outside this plan's implementation ownership.

## Solution Architecture

Use a narrow test-only repair. In the two tests that create an isolated matrix
workspace, pass that workspace directory as `repoRoot`. The absolute review
paths remain valid, existing validation dependencies remain mocked, and
`git ls-files` returns an empty fixture-scoped source universe. Approval, review
rebinding, failure injection, generated-artifact installation, rollback, and
cleanup still execute.

Do not increase timeout, weaken assertions, modify production rollback code, or
accept a rerun-only green result. The test file is absent from the signed source
inventory, so this specific repair does not stale matrix source hashes.

PR #1380 is a downstream handoff, not a parallel merge. It may finish review and
remain ready while G3/G4 complete, but merging it before G4 changes main and
therefore creates a new release candidate requiring full G3 reapproval.

## Technical Considerations

- **Pattern usage:** preserve fail-closed surface-matrix validation and atomic
  write-set rollback. Dependency automation cannot bypass signed evidence.
- **Worktree isolation:** current checkout contains unrelated user changes and
  must not be switched, cleaned, reset, committed, or used for repair.
- **GitHub state:** Vercel pending is not a required branch-protection context.
  Required gate is `CI Gate Status` with strict base freshness.
- **Squash semantics:** source/closure commit provenance remains recorded in PR
  and signed evidence; `M1` is matrix closure and successor `M2` becomes release
  identity only after Child F plus replacement approval when required.
- **Ownership:** no #1380 source, branch, review, or GitHub mutation from this
  task.
- **Edge cases:** fresh CI runs against a changed head, failure category
  changes, merge-base advances, squash proof differs from PR proof, test repair
  changes signed evidence, #1380 completes before G4, or main auto-deploys
  unapproved post-G4 changes.
- **Rollback:** before G4, revert via a new PR and repeat G3 proof. After G4,
  rollback uses the governed three-unit revert-release workflow defined by
  F_1.2.0; historical SHA re-release is forbidden by the main-head fence.
