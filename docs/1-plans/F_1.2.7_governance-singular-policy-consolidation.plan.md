# Governance Singular-Policy Consolidation Implementation Plan

Governing policy:
`docs/governance/solo-internal-change-and-production-policy.md`.

## Overview

Adopt a singular governance authority model: the existing solo-internal policy
becomes the explicit constitution with a document-roles-and-precedence section;
`CLAUDE.md` and `AGENTS.md` are reduced to short entry loaders that route to it;
`CI Gate Status` remains the sole aggregate merge gate; the surface-contract
matrix is split by component role (data = evidence, validators = scoped
enforcement, G1 record = scoped review evidence); the PR-#1385 capture workflow
is marked as a one-time program-scoped artifact. Hierarchy compliance is
enforced by extending the existing
`tests/unit/docs/production-governance-routing.test.ts`, which runs inside the
required `CI Gate Status` rollup.

## Problem Statement

Governance diverged through policy layering without binding precedence: a merge
module (May-June 2026), action-specific production controls (July-August), the
470-row surface-contract matrix with a G1 gate (August 5, commit `081bd1d9e`),
the solo-internal policy (August 14, commit `b7f81f3cc`) that never retired the
older matrix/G1 approval semantics, a PR-#1385-specific capture workflow (commit
`a472f4626`), and an August 18 external release plan that consulted no governing
document and self-declared its evidence chain as authority. The entry documents
`CLAUDE.md` and `AGENTS.md` reference the ACTIVE policy zero times, so nothing
forces any workflow to load the governing document first. Two adversarial
reviews (32-agent red team; deliberation/red-team document dated 2026-08-18)
converged on the same defect and on required revisions folded into this plan.

## Solution Architecture

One constitution (the existing policy, amended additively), one aggregate merge
gate (`CI Gate Status`, confirmed required by branch protection on `main`), one
production route (`docs/workflows/PRODUCTION_SCRIPTS.md`), entry documents
reduced to loaders, and every other artifact classified evidence or rationale.
Enforcement of the hierarchy itself rides the existing merge gate via new
assertions in `tests/unit/docs/production-governance-routing.test.ts` — no new
governance machinery. Work splits into two PRs so no file collides with open PR
#1385: PR A (files verified disjoint from #1385's diff) now; PR B
(`audit/surface-contract-matrix/README.md`, `DECISIONS.md`, generated router
artifacts) after #1385 reaches a terminal state.

Ratified decisions this plan implements:

- Q1 (conditional A): adopt one authority model expressed as document ROLES plus
  explicit precedence rules — not ordinal ranks (load order and precedence are
  separate concerns).
- Q2 (A with lifecycle): `.github/workflows/capture-release-baseline.yml` stays
  operational while the #1385 program is active; it gains a comment-level
  lifecycle contract (owner, terminal condition, explicit non-authorization);
  archival happens after the terminal condition via the Archive Gate.
- Q3 (component-role split): matrix data/inventories are evidence; the validator
  suite in `tests/unit/audit/surface-contract-matrix.test.ts` (exact-set,
  source-hash, closed-phase downgrade protection) is retained scoped merge
  enforcement and the NAMED pre-merge provenance control; the G1 review record
  is scoped review evidence invoked only by explicit owner directive for a named
  program — never generic merge or release approval.

Red-team recommendations deliberately rejected (owner-ratified at plan approval;
each has a cheap later escalation path if a second incident proves need): (1)
13-field production authorization record with nonces/revocation — replaced by
one policy sentence naming the sole production-dispatch issuer (repository owner
via explicit workflow dispatch); (2) provider decoupling/fencing as an adoption
blocker — production topology is owned by the G3/G4 program (ADR-075); the
policy instead states the coupling honestly; (3) `decision_scope` output fields
in `ci-unified.yml` — no consumer, YAGNI, and the file is owned by #1385's diff;
(4) refusal logic inside the capture workflow now — its parsed YAML structure is
pinned by `tests/regressions/ci-fail-closed.test.ts` and the program is
mid-flight; (5) a generated shared governance block for the two loaders — a
parity test suffices.

## Implementation Details

### 1. Policy additions (additive only)

**File**: `docs/governance/solo-internal-change-and-production-policy.md`

All existing text and test-pinned strings preserved; new sections appended:

- `## Document roles and precedence`: role table without ordinal numbering —
  entry loaders (`AGENTS.md`/`CLAUDE.md`), constitution (this policy), merge
  gate (`CI Gate Status` via branch protection; `.github/path-filters.yml` is
  its changed-path classifier, not an authority), production procedure
  (`docs/workflows/PRODUCTION_SCRIPTS.md` plus production workflows),
  evidence/diagnostics (matrix artifacts, G1 records, reviews, receipts, plans),
  rationale (ADRs, architecture reviews). Precedence rules: load order is
  separate from precedence; on conflict this policy prevails; missing, stale,
  conflicting, or UNKNOWN authority fails closed; more-specific rules may add
  restrictions but never relax a floor; enforcement may block but cannot create
  authority; evidence satisfies only explicitly named predicates; catch-all —
  any artifact not named here (skills, agent profiles, cheatsheets, prompts,
  plans) is procedure or reference at most and can never grant authority;
  resolve this policy from the protected target branch (`origin/main`), never
  from a working branch.
- Amendment clause (prospective from adoption): this policy amends only by a PR
  that modifies this file plus an ADR entry; plans, reviews, matrices, and
  generated artifacts cannot amend it. Bootstrap exception: this founding
  amendment is ratified by owner approval of this plan (recorded in the PR A
  description) and its ADR lands in PR B, because `DECISIONS.md` is inside open
  PR #1385's diff and must not conflict.
- Production-dispatch issuer: the repository owner, via explicit dispatch of the
  named workflow; no agent, plan, or artifact self-authorizes.
- Provider-coupling statement: merge to `main` may causally trigger provider
  deployment under current topology (ADR-075); that coupling is a topology fact,
  not an authorization; a merge that would mutate production is
  production-affecting and takes the production-action route.
- Matrix component split (Q3) including the named provenance successor
  (`tests/unit/audit/surface-contract-matrix.test.ts` validator suite) and the
  G1 demotion sentence.
- `## Documentation governance`: Archive Gate, prune/preserve rules,
  derivability test, Phoenix protected paths with required-reviewer table and
  cleanup tier table — moved near-verbatim from `CLAUDE.md`. Pointer-intact
  move: `.claude/PHOENIX-AGENTS-REGISTRY.md`, `.claude/PHOENIX-TOOL-ROUTING.md`
  and Phoenix sections of `.claude/DISCOVERY-MAP.md` are untouched.

## Technical Considerations

- **Pattern usage**: hierarchy enforcement extends the existing routing-test
  pattern (pinned strings, grandfathered lists) instead of adding a new gate;
  policy edits are strictly additive so existing pinned strings survive.
- **Conflict avoidance**: PR A's file set is verified disjoint from PR #1385's
  diff (61 files at head `aef28504463ae5258c4069f468d10bf3f5cedd28` against base
  `94f459700346965c41a264fb9f124bb97f33b214`; `CHANGELOG.md` is not in that
  diff). The would-conflict surfaces (matrix README, `DECISIONS.md`,
  `docs/_generated/*`) are deferred to PR B. Phase 1 re-proves disjointness at
  implementation time with an exact intersection command against the pinned SHAs
  (expected empty).
- **Docs routing**: PR A ships the new plan path WITHOUT regenerating
  `docs/_generated/*` — CI's `docs-routing-check.yml` runs
  `docs:routing:check:ci` (`--allow-doc-inventory-drift`), verified tolerant of
  the single-path inventory drift. Strict `docs:routing:generate` +
  `docs:routing:check` run in PR B after #1385's generated-artifact churn lands.
- **Auto-load loss**: rules stripped from loaders stop reaching sessions
  automatically; mitigated by the KEEP-IN-STUB set, one-hop routing rows, and
  the parity test.
- **Edge cases**: stale working branches predating the policy (mitigated by the
  origin/main resolution rule in both loaders and the policy); Phoenix-locked
  files untouched (rule text moves verbatim; fallback keeps the Phoenix
  subsection in the stub if the domain-lock is read more strictly).
