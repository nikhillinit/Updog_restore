## Overview

Build the pure V2 internal-economics derivation core: a stateless,
side-effect-free computation that takes one immutable, strictly validated,
JSON-safe input and produces an authoritative selected-lane economics receipt,
plus an independent reserve funding-source classifier, plus an explicit
dual-lane certification harness for CI. V1 remains byte-frozen; V2 admits only
the literal contract version `internal-economics-composite/2.0.0` and refuses
everything else.

F_2.0.0 ships no user-visible capability and changes no operating-partner
workflow. No routes, persistence, jobs, activation, migrations, provider
configuration, or production mutation. Its definition of done is a replayable,
truth-corpus-verified core: green hand-computed corpus for both waterfall lanes,
a working certification harness, and a V1 freeze proof.

No new dependencies: Decimal.js, Zod, Vitest, fast-check, and Node crypto are
already present (`package.json:320`, `:360`).

## Problem Statement

The current internal-economics engine is single-version with no discriminator,
no contract boundary between derivation and consumers, and no separation of
deal-by-deal vs whole-fund waterfall semantics. Adding V2 capabilities
(pure-input derivation, both waterfall engines, settled-cash bases, LP-class fee
attribution, explicit lot provenance, independent recycling caps, reserve
funding-source classification) requires a versioned, refusal-first V2 core built
beside frozen V1 without touching it.

## Solution Architecture

Four pure internal TypeScript entry points. No version dispatch caller, no V1
fallback, no I/O anywhere:

```ts
verifyAndNormalizeInternalEconomicsInputV2(input: unknown):
  | { ok: true; input: NormalizedInternalEconomicsInputV2 }
  | { ok: false; refusal: V2CoreRefusal };

deriveInternalEconomicsCompositeV2(input: NormalizedInternalEconomicsInputV2):
  | { ok: true; receipt: InternalEconomicsReceiptV2 }
  | { ok: false; refusal: V2CoreRefusal };

certifyInternalEconomicsDualLaneV2(input: NormalizedInternalEconomicsInputV2):
  | { ok: true; certification: V2DualLaneCertification }
  | { ok: false; refusal: V2CoreRefusal };

classifyReserveFundingSourcesV2(receipt: InternalEconomicsReceiptV2):
  | { ok: true; sources: ReserveFundingSourcesV2 }
  | { ok: false; refusal: V2ReserveRefusal };
```

- `NormalizedInternalEconomicsInputV2` is a branded type produced only by the
  normalization factory. The composite accepts nothing else; normalization is
  structural, not conventional.
- Version admission: literal `internal-economics-composite/2.0.0` required.
  Missing or unknown versions refuse
  (`UNSUPPORTED_INTERNAL_ECONOMICS_CONTRACT_VERSION`). F_2.0.0 implements no
  missing-version-to-V1 fallback; caller dispatch and legacy routing (with
  stored version-tuple proof) are F_2.1.0. This closes the silent-downgrade
  channel where a dropped discriminator evades every V2 refusal.
- Ordinary derivation executes only the selected lane and returns no
  certification-lane data. Certification runs both engines from identical
  immutable normalized input and compares only shared invariants (conservation,
  non-negativity, allocation sums) — never cross-lane output equality, because
  the two lanes are different economics and divergence is expected. Per-lane
  expected-output comparison against the truth corpus is owned by the corpus
  runner (a test suite), not by the certifier: the runner feeds each corpus case
  through derivation/certification and asserts lane outputs against the corpus
  expectations.
- The reserve classifier is a read-only consumer of the receipt. Its refusal
  never invalidates the economics receipt.

### Numeric authority

- Internal math: `Decimal` from `decimal.js` under the repo-global config
  (precision 28, `ROUND_HALF_UP`, `shared/lib/decimal-config.ts:4-14`). No
  `half_even` anywhere: it does not exist in `shared/` today and a fork would
  either break the V1 freeze (global flip) or split the numeric authority
  (per-op). The global config is never mutated.
- Contract boundary: canonical signed fixed-6-place decimal strings for money
  and 12-place for ratios, reusing `shared/lib/decimal-string.ts:5-10` schemas.
  JavaScript `number` is forbidden for authoritative money.
  `shared/schemas/reserves-schemas.ts:12` `MoneySchema` (float, positive-only,
  excludes zero) is not reused.
- Cents: new `decimal-cents-v2.ts` provides exact Decimal-string/Decimal to
  `bigint` cents conversion (HALF_UP applied only at the payable-allocation
  boundary; full precision retained upstream) and hierarchical largest-remainder
  apportionment (ADR-065 precedent,
  `shared/lib/internal-economics/presentation-rounding-v1.ts:80-129`).
  `shared/lib/cents.ts` (`toCents(n: number)` via `Math.round`, `cents.ts:3-5`)
  is not reused.
- Hashing: normalized-input and result hashes are SHA-256 over canonical JSON
  after decimal-leaf canonicalization (`shared/lib/decimal-string.ts:73-75`),
  recorded with a versioned `hashAlgorithm` field (`canonical-json-sha256/1`).
  `shared/lib/canonical-hash.ts` is not used as-is for financial payloads: it
  drops `undefined`-valued keys and has no Decimal or byte branch
  (`canonical-hash.ts:3-28`). No `Uint8Array` sealed-bytes fields exist in
  F_2.0.0; the raw-byte preimage format is pinned spec-only in ADR-085 and
  implemented at the F_2.1.0 persistence boundary, where the real trust boundary
  is. Policy and configuration are supplied once as typed, strictly validated
  JSON-safe structures — there is no bytes-plus-typed-mirror duplication and
  therefore no mirror-mismatch failure class.

Money fields are canonical 6-place decimal strings on the wire, `Decimal` after
normalization.

**Window and calendar invariants** (violations refuse at normalization):

- `fundEstablishmentDate <= investmentPeriodEndDate <= fundTermDate`
- `fundEstablishmentDate <= cutoverInstant <= calculationDate`
- Every event satisfies `cutoverInstant < event.instant <= calculationDate`; any
  event at or before cutover, or after the calculation date, refuses
  `EVENT_OUT_OF_WINDOW` (this single code covers both ends of the window).
- `calculationDate` may exceed `fundTermDate` (post-term wind-down is a real
  state); preferred-return accrual behavior past term follows the ADR-085
  terminal-stub rule, with a corpus case.

**FeeProfileV2WireSchema.** The existing `FeeProfileSchema` cannot sit on the V2
wire: its decimal primitive admits `number | string | Decimal`
(`shared/schemas/decimal-zod.ts:10`) and its object schemas are non-strict
(unknown keys stripped, `shared/schemas/fee-profile.ts:222`), while V2 canonical
hashing rejects `Decimal` instances (`shared/lib/decimal-string.ts:49-58`). The
input contract therefore defines `FeeProfileV2WireSchema`: a recursively strict
(`.strict()` at every level), decimal-string-only mirror of the FeeProfile
shape. Normalization validates the wire form, includes the canonical wire
strings in the normalized-input hash, and only then transforms to a `FeeProfile`
instance (Decimal-bearing) for reuse of existing fee behavior. Unknown keys,
numeric money, or `Decimal` instances on the wire refuse
`SCHEMA_VALIDATION_FAILED`.

**Opening reconciliation invariants** (violation refuses
`OPENING_RECONCILIATION_VIOLATION`, exact cents equality):

- scalar totals equal ledger sums for accrued preference, cumulative
  distributions, consumed fee recycling, consumed exit recycling, and unreturned
  settled cash capital
- `openingCommitments == sum(investorLedgers[].committedCapital)`
- intra-ledger identities: `committedCapital >= calledCapital`; non-negativity
  of all ledger balances
- `openingCumulativeFees` is trusted via provenance references — it is NOT
  recomputed from events, because events are post-cutover only (full-history
  replay is rejected: it re-opens double-counting in every processor and the
  pure core cannot authenticate history anyway)
- opening cash carries an explicit classification that fully partitions it:
  `paidIn + recycling + unclassified == openingCash` to exact cents (violation
  refuses `OPENING_RECONCILIATION_VIOLATION`). Unclassified opening cash is
  supported input — it is permanently reserve-ineligible but never, by itself, a
  refusal (see section 9)

### 2. Tier grammar

```ts
type WaterfallTierV2 =
  | { kind: 'return_of_capital'; priority: number }
  | {
      kind: 'preferred_return';
      priority: number;
      basis: 'unreturned_settled_cash_capital';
      annualRate: RatioDecimalString;
      rateMode: 'simple' | 'effective_annual_compounded';
    }
  | {
      kind: 'gp_catch_up';
      priority: number;
      gpAllocationRate: RatioDecimalString;
    }
  | { kind: 'carry'; priority: number; gpShare: RatioDecimalString };
```

Validation (violation refuses `INVALID_TIER_POLICY` or
`UNSUPPORTED_TIER_FEATURE`): priorities start at one, unique, contiguous; each
kind at most once; carry exactly once and last; ROC and preferred return may be
omitted or appear in either order; catch-up requires preferred return, sits
immediately before carry, targets the terminal carry share, and its GP
allocation exceeds the terminal carry share and is at most one. Clawback,
escrow, hybrid scope, and alternative preferred-return bases refuse. The
existing `shared/schemas/waterfall-policy.ts` is not reused for V2 policy: it is
American-only and admits clawback configuration (`waterfall-policy.ts:66-78`,
`:122-136`).

**Catch-up stopping rule (normative).** The `gp_catch_up` tier allocates each
distributable profit dollar `gpAllocationRate` to the GP and the remainder to
LPs, and stops when cumulative GP profit equals `gpShare` of cumulative profit
distributed, where profit = preferred return + catch-up + carry (ROC excluded).
For a clean opening state the gross catch-up tier total is
`preferredPaid x gpShare / (gpAllocationRate - gpShare)` (denominator positive
by the validation rule above); partial catch-up simply stops at the target when
proceeds run out. For mid-life resume the remaining target is computed from
opening cumulative figures, which requires an opening profit-tier decomposition
in the input contract: `openingCumulativePreferredPaid`,
`openingCumulativeGpProfitDistributions`, and
`openingCumulativeLpProfitDistributions` — fund-level for the whole-fund lane
and per entitlement pool for the deal-by-deal lane — each reconciled against
`openingCumulativeDistributions` (`OPENING_RECONCILIATION_VIOLATION` otherwise).
A mid-life catch-up continuation case is part of the corpus coverage floor.

### 3. Chronology engine

**File**: `shared/lib/internal-economics/v2/event-stream-engine-v2.ts` (new).

Canonical same-instant order:

1. settled funding and equalization
2. freeze fee and preferred-return bases
3. fees and expenses
4. realizations and recycling classification
5. monthly preferred-return posting
6. selected waterfall
7. deployment (ordinary and eligible recycled)
8. closing reconciliation

Tie-breaking: instant, then phase/class priority, then dependency order
(correction events follow their referenced contribution within the same
instant), then stable structured event identity. Reversals and supersession are
resolved upstream; F_2.0.0 accepts only terminal canonical events.

**Derived events in chronology.** `management_fee_payment` joins phase 3 (fees
and expenses) at its fee-assessment instant; `distribution` joins phase 6
(selected waterfall) at its allocation instant. Within a phase, derived events
sort after caller events of the same phase. Their `derivedEventId` is unique
within the derived stream.

This file also owns callable-commitment tracking: consumed by actual deployment,
management-fee, fund-expense, and equalization-principal calls; recipient
equalization ROC restores the same recipient's callable capacity; GP cash
follows call purpose; GP deemed contribution consumes none; negative schedules
or commitment overruns refuse (`COMMITMENT_OVERRUN`); calls are sized before the
waterfall and payouts cannot recursively resize calls.

### 4. Monthly preferred-return accrual kernel

**File**: `shared/lib/internal-economics/v2/preferred-return-accrual-v2.ts`
(new).

Monthly canonical grain per ADR-069 (`DECISIONS.md:9979-9986`); no day-count
proration. `quarterly-schedule-compiler-v1.ts` is not reused — verified to
contain no usable calendar math (`quarterly-schedule-compiler-v1.ts:60-93`); the
kernel builds canonical monthly periods itself.

- Accrues only on unreturned settled cash capital.
- `simple`: `annualRate x months / 12`; accrued preference excluded from base.
- `effective_annual_compounded`: monthly rate `(1 + annualRate)^(1/12) - 1`;
  unpaid preference joins the following month's base.
- Posts when `periodEnd <= distributionDate`; month-end distributions see that
  month's posting; mid-month distributions see only the prior month-end posting
  (ratified in ADR-085 with a corpus case — daily piecewise accrual is rejected
  for V2.0.0 as unanchored to any verified LPA term and contrary to ADR-069).
- Stub months (establishment month, final month) behave exactly as ADR-085
  defines, with corpus cases for both.
- Full Decimal precision retained; only payable allocations cross the exact
  bigint-cent boundary.
- GP deemed contribution never enters cash, fee, ROC, preferred-return, paid-in,
  clawback, or IRR bases (ADR-070).

### 5. Waterfall engines and certification

**Files**: `shared/lib/internal-economics/v2/waterfall-deal-by-deal-v2.ts`,
`shared/lib/internal-economics/v2/waterfall-whole-fund-v2.ts` (new).

- Deal-by-deal owns deal/security/investment-lot entitlement pools and forbids
  cross-deal subsidy. Entitlement computed once per pool; allocation uses exact
  Decimal arithmetic with largest-remainder cents; source identity breaks only
  rounding ties.
- Whole-fund owns fund-level capital accounts and defers carry until fund-wide
  tier obligations are satisfied.
- Both share chronology, tier-allocation primitives, Decimal helpers, and cent
  apportionment; lane state machines are separate; inputs are
  deep-frozen/structurally cloned at the lane boundary so no shared mutable
  state can leak between lanes.
- Ordinary derivation executes only `selectedLane` and returns no
  certification-lane data. This respects ADR-066/068: whole-fund vocabulary is
  restored, but live whole-fund output must not become shadow accounting through
  an always-on runtime field.
- `certifyInternalEconomicsDualLaneV2` is the only dual-execution path: both
  engines run from identical immutable normalized input; shared invariants are
  compared; consumed by CI and the truth harness only. Expected-output
  assertions per lane live in the corpus runner tests, which are the comparator
  the certifier itself does not carry.

### 6. Fee attribution and recycling

**File**: `shared/lib/internal-economics/v2/fee-recycling-enforcer-v2.ts` (new;
invoked from the event-stream engine).

- FeeProfile is the sole V2 fee authority; full behavior reused (tiers,
  holidays, retroactive catch-up, fee recycling) via
  `shared/schemas/fee-profile.ts`. Fee bases are LP-class attributable; GP
  populations excluded. Legacy Plan/Forecast fee drag is structurally disabled
  on the V2 path: normalization has no fee-drag fields, so `fee-drag-compiler`
  is never invoked. V1 paths — including
  `shared/lib/current-plan/derive-current-plan-v1.ts:13-16,122-126`, a V1
  location the freeze inventory must include — continue unchanged.
- `called_capital_period` counts settled LP deployment contributions only. Fee,
  expense, equalization, facility, and deemed legs are excluded. Negative
  deployment-call corrections net within the same half-open period; a correction
  that would drive the period basis negative refuses (`NEGATIVE_PERIOD_BASIS`) —
  no silent floor-at-zero (refuse-don't-clamp), unless ADR-085 explicitly
  ratifies flooring.
- Fee and exit recycling use independent, nonfungible caps; each realized event
  is tagged `fee` or `exit`, never both.
- Fee recycling cap: V2 constrains `recyclingPolicy.basis` to cumulative bases
  (committed capital / cumulative called). Per-period and dynamic
  (FMV/unrealized) bases refuse `UNSUPPORTED_V2_RECYCLING_BASIS`: the verified
  dimensional mismatch (per-period allowance minus lifetime consumption,
  `fee-profile.ts:319-333`, `:636-652`) and the drop-prone dynamic-basis ratchet
  are not solvable in this plan; high-water-mark semantics are F_2.2.0+ if ever.
  Within cumulative bases, `calculateRecyclableFees` (`fee-profile.ts:658-679`)
  is reused with context derived from normalized fields (committed capital from
  ledgers, `currentMonth` from the epoch). Available capacity = lifetime cap
  minus (opening consumed + current-run consumed); a negative result refuses
  (`RECYCLING_CAPACITY_EXCEEDED`) — the `Decimal.max(0, ...)` clamp is rejected
  as doctrine violation. Disabled/absent/expired policy means fee events
  classify non-recyclable and capacity is zero (verified helper behavior,
  `fee-profile.ts:663-671`); a recycling event against a disabled policy refuses
  (`FEE_RECYCLING_DISABLED` narrowed to that explicit conflict).
- Exit recycling cap: sealed committed-capital percentage times committed
  capital, minus consumed exit recycling. This is a deliberate semantic change
  from V1's proceeds-based pool
  (`shared/lib/economics/economics-engine.ts:555-563`) and is named and tested
  as such. Retained recycling floors to cents via largest remainder; the exact
  excess remains distributable.

### 7. Equalization (reserved, refused by default)

**Namespace reserved in the input contract and refusal union; no mechanics
implemented in V2.0.0 unless ADR-085 enables them with truth cases.**

- Default: any equalization event refuses `UNSUPPORTED_V2_EQUALIZATION`.
- Reserved semantics (for the ADR to enable, `canonical_lrm_v1`): principal is
  balanced payer contribution vs recipient ROC, net-zero to fund cash; recipient
  ROC cannot exceed pre-leg unreturned settled cash capital; interest is a
  direct LP-to-LP non-capital flow affecting payer/recipient XIRR vectors only.
  Engine-generated allocations use deterministic largest-remainder cents
  (ADR-065 precedent); caller-supplied legs are recomputed canonically and
  refuse on mismatch (`EQUALIZATION_MISMATCH`) — repair of caller-supplied money
  is never silent.
- Rationale: zero equalization prior art exists in the repo; inventing rate
  source, day-count, and retroactive-pref interaction without worked examples
  would let plausible defaults become durable fund-accounting facts.

### 8. Receipt

**Files**:
`shared/contracts/internal-economics/internal-economics-receipt-v2.contract.ts`
(new), `shared/lib/internal-economics/v2/liquidity-receipt-builder-v2.ts` (new).

`InternalEconomicsReceiptV2` contains:

- Contract, engine, methodology, normalization, and period-model versions
  (`componentVersions` asserted, not inert).
- Selected lane identity and selected-lane results only. No certification-lane
  data.
- Opening-state and source-artifact references; normalized-input and result
  hashes with `hashAlgorithm`.
- Fund cash equation and remaining cash-source-lot balances:
  `opening cash + settled external calls + realized proceeds - fees - expenses - investments - distributions = ending cash`.
  Equalization principal (if ever enabled) is net-zero fund cash. Recycling is a
  classification, not a cash source. Violation refuses
  `RECEIPT_CONSERVATION_VIOLATION` (stage-distinct from the opening code,
  matching the three-code precedent in
  `shared/contracts/internal-economics/lp-economics-run-receipt-v1.contract.ts:30,40-41`).
- Per-partner, per-class, and per-entitlement-pool ledgers; fees, expenses, ROC,
  preference, catch-up, carry, investment distributions.
- Canonical per-partner cash-flow vectors (decimal strings, UTC instants). No
  XIRR numbers: the existing solver is `number`/`Date`-based
  (`shared/lib/finance/xirr.ts`) and per-partner XIRR computation is deferred to
  consumers (F_2.2.0) or a later exact-Decimal utility.
- No reserve classification.

A failed derivation returns a refusal, never a partial receipt.

### 9. Reserve funding-source classifier

**Files**:
`shared/contracts/internal-economics/reserve-funding-sources-v2.contract.ts`
(new), `shared/lib/internal-economics/v2/reserve-funding-classifier-v2.ts`
(new).

```ts
interface ReserveFundingSourcesV2 {
  remainingCallableCommitmentUsd: MoneyDecimalString; // non-cash, legal capacity
  eligiblePaidInCashUsd: MoneyDecimalString;
  eligibleRecyclingCashUsd: MoneyDecimalString;
}
```

- No total that adds callable commitment to cash is ever exposed — the category
  error is structural, not presentational. Documentation records the
  conventional drawdown ordering (recycling cash, then paid-in cash, then
  callable commitment) without summing.
- Paid-in and recycling cash lots are mutually exclusive and reconcile exactly
  to classified eligible ending cash (`RESERVE_CONSERVATION_VIOLATION`
  otherwise).
- Exclusions: unrealized proceeds, empty cap headroom, facilities, GP deemed
  contribution, equalization transfers, distributable/non-recyclable proceeds,
  unclassified remaining opening cash.
- The classifier cannot recalculate economics, fetch configuration, or mutate
  the receipt. It refuses classification (`V2ReserveRefusal`) on three disjoint
  predicates: `MISSING_PROVENANCE` (a cash source or lot lacks its provenance
  reference), `RESERVE_BUCKET_OVERLAP` (a lot appears in more than one bucket),
  or `RESERVE_CONSERVATION_VIOLATION` (classified bucket totals fail to
  reconcile to eligible ending cash). Reconciled unclassified cash is supported
  input — it is simply excluded from every bucket, and no refusal fires.
- Placement: `shared/lib`, not `server/services` — pure math stays in the
  authoritative shared layer (`docs/STABILIZATION-ROADMAP.md:339-344`; zero
  shared-to-server imports exist today).

### 10. Refusal contract

`V2CoreRefusal`:

```ts
interface V2CoreRefusal {
  readonly ok: false;
  readonly code: V2RefusalCode; // literal union, stable
  readonly stage: V2Stage; // typed enum
  readonly message: string;
  readonly diagnostics?: V2RefusalDiagnostics; // bounded; never financial outputs
}
```

- `V2Stage`:
  `normalization | admission | chronology | settlement | provenance | accrual | equalization | waterfall | recycling | receipt`.
- `diagnostics` may carry `periodIndex`, `eventId`, `partnerId`,
  `expectedCents`, `actualCents`, `deltaCents`, `contextDetails` — bounded debug
  context for the solo maintainer. Fail-closed applies to certified financial
  outputs (receipt, reserve, lane results), which are never present on refusal;
  V1 error precedent already carries context without outputs
  (`decimal-waterfall-core-v1.ts:107-120`).
- Stable codes (each with an enumerated producer call-site and a reachability
  test): `UNSUPPORTED_INTERNAL_ECONOMICS_CONTRACT_VERSION`,
  `SCHEMA_VALIDATION_FAILED`, `ADMISSION_LIMIT_EXCEEDED`, `EVENT_OUT_OF_WINDOW`,
  `DUPLICATE_EVENT_IDENTITY`, `OPENING_RECONCILIATION_VIOLATION`,
  `LP_CLASS_PROFILE_AMBIGUITY`, `UNSUPPORTED_MULTI_CLASS_FEE_DIVERGENCE`,
  `GP_SPLIT_MISMATCH`, `CASH_SOURCE_ALLOCATION_VIOLATION`,
  `INVESTMENT_LOT_RELIEF_VIOLATION`, `UNSUPPORTED_V2_WATERFALL_HYBRID`,
  `INVALID_TIER_POLICY`, `UNSUPPORTED_TIER_FEATURE`, `COMMITMENT_OVERRUN`,
  `UNSUPPORTED_V2_EQUALIZATION`, `EQUALIZATION_MISMATCH`,
  `NEGATIVE_PERIOD_BASIS`, `UNSUPPORTED_V2_RECYCLING_BASIS`,
  `RECYCLING_CAPACITY_EXCEEDED`, `FEE_RECYCLING_DISABLED`,
  `RECEIPT_CONSERVATION_VIOLATION`, `FEE_ALLOCATION_MISMATCH`.
- Reserve refusals are a separate union with disjoint predicates:
  - `MISSING_PROVENANCE` — a cash source or lot lacks its required provenance
    reference entirely (a structural absence, not an arithmetic failure).
  - `RESERVE_BUCKET_OVERLAP` — a single cash-source lot is assigned to more than
    one bucket (double-assignment).
  - `RESERVE_CONSERVATION_VIOLATION` — the sum of classified eligible buckets
    does not equal classified eligible ending cash (the totals don't reconcile,
    as distinct from unclassified-cash exclusion). There is no
    `UNCLASSIFIED_REMAINING_CASH` and no `CLASSIFICATION_MISMATCH`: reconciled
    unclassified cash is valid and simply excluded; totals that fail to
    reconcile are `RESERVE_CONSERVATION_VIOLATION`.

## Technical Considerations

- **Pattern usage**: contract filenames follow repo convention
  (`name-v2.contract.ts`, matching `*-v1.contract.ts` / `*-v1.1.contract.ts`
  precedent; semver belongs in the contract string, not the filename). Receipt
  and reserve contracts version with the V2 family
  (`internal-economics-receipt/2.0.0`, `reserve-funding-sources/2.0.0`);
  per-artifact versioning divergence is permitted by precedent but not needed
  here.
- **V1 freeze**: V1 code is never modified. V2 lives in new files under
  `shared/lib/internal-economics/v2/` and
  `shared/contracts/internal-economics/`. V2 imports no V1 waterfall logic: the
  internal V1 core has no preferred-return or tier machinery to reuse
  (`decimal-waterfall-core-v1.ts:53-55`, `:383-388`).
- **ADR-083 classification**: financial-truth change; requires
  `TZ=UTC npm run phoenix:truth` green plus named expected-output assertions.
  `calc-gate` is run as a deliberate adoption for this path (policy:
  `docs/governance/solo-internal-change-and-production-policy.md:60-68`), not
  claimed as a universal ADR-083 mandate.
- **Edge cases**: same-instant events in both lanes; exit recycling cap at
  exactly zero remaining capacity; amounts above `Number.MAX_SAFE_INTEGER`
  (bigint cents); BIGINT row versions (contract types safe for F_2.1.0); GP
  deemed exclusion from all bases; zero-value legs still validated.
