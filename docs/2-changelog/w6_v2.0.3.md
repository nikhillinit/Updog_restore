## Changes

### V2 F3a Cumulative Allocation Validation (F_2.0.3)

Closes the F3a repeated-row and ignored-refusal defects in the V2 internal
economics event-stream engine without widening public V2 capability.
Computation-only; no routes, persistence, queues, flags, UI, schema, or
production action. F2 public event admission remains refused.

- **Cumulative per-lot validation**: `validateCashSourceAllocations` and
  `validateReliefRows` now scan all references first (missing reference wins),
  reject negative allocation/relief/proceeds rows at row level, then aggregate
  amounts per lot and compare each aggregate against the lot's remaining balance
  / remaining cost basis. Repeated rows that are individually valid but
  cumulatively overdraw now refuse with the existing refusal families at the
  provenance stage.
- **Exact event-total validation**: `processDeployment` and `processFundExpense`
  compare the cash-source allocation sum against event `amountUsd`;
  `processRealization` compares the allocated-proceeds sum. Mismatches refuse
  after validation and before any mutation with the plan-pinned literal message
  and byte-exact `contextDetails` JSON (six-place decimal strings).
- **Refusal propagation**: the chronology loop in `derive-composite-v2.ts` is
  exported unchanged in order as `processEventsV2ForTest` and now returns the
  first refusal from refusal-capable processors instead of dropping it;
  `runLane` calls it. A later-event refusal leaves earlier committed effects
  intact and applies zero of its own.
- **No surface change**: contract stays `internal-economics-composite/2.0.1`,
  receipt stays `internal-economics-receipt/2.1.0`; no new refusal family, code,
  or diagnostic contract field; no `sourceCashLotId`; zero-event opening input
  keeps the unchanged F2 receipt/hash.
- **Tests**: 16 new cases in `event-stream-engine-v2.test.ts` — five
  regression-green baselines (three state-unchanged-on-refusal snapshots plus
  valid repeated cash/relief rows) and eleven expected-red cases turned green
  (cumulative overdraw, total mismatch, negative rows, chronology first-refusal
  with earlier-effect retention, and both precedence ladders). Every refusal
  case asserts full before/after mutable-state equality.
- **Governance**: ADR-088 records the decision to repair validation order,
  repeated-row aggregation, exact totals, and refusal propagation through the
  existing chronology switch before source lineage, receipts, persistence, or
  queues. `sourceCashLotId` lineage, eventful receipt, event-stream atomicity,
  correction/write-off/conversion, and persistence/BullMQ remain later F3 gates.
