## Changes

Governed production release path: `release-production.yml` is mechanically
unblocked and gains an exact-SHA Railway worker deployment capability.

- Removed the `production-mutation-block` job and the `if: false` guards on
  `stage-production` and `promote`; `validate-target` no longer depends on the
  blocker.
- New `scripts/release/deploy-railway-workers.mjs`: fixed-purpose helper
  deploying exactly `fund-scenario-calc` then `capital-call-status` serially at
  the exact candidate SHA via `serviceInstanceDeployV2`. Per service it
  re-fences live `refs/heads/main` (git ls-remote), verifies project/environment
  scope and tolerant worker topology, gates on the
  `serviceInstanceAutoDeployStatus` readback (`enabled === false` for both
  services or fail closed), reuses an active successful exact-SHA deployment
  only after re-reading it through the exact-ID path (service, environment,
  `SUCCESS`, `meta.commitHash`, `deploymentStopped === false`), waits on the
  exact returned deployment ID, and on second-service failure recovers the first
  by `deploymentRollback` (Boolean result; new active deployment re-resolved and
  commit-verified) or `deploymentRedeploy`. Ambiguous mutation failures
  reconcile read-after-error into `unconfirmed` handles; every BLOCKED result
  carries all deployment handles and the workflow prints the redacted result
  JSON to log and step summary.
- New `scripts/release/railway-graphql-transport.mjs`: shared endpoint constant
  and `Project-Access-Token`-authenticated GraphQL POST helper;
  `collect-provider-evidence.mjs` and `wait-railway-workers.mjs` migrated.
- `wait-railway-workers.mjs`: optional expected deployment-ID verification; the
  deploy job's returned IDs flow through `railway-workers-verify` and into
  `staged-provider-identity` via new optional expected-ID arguments on
  `verify-provider-identity.mjs`.
- Two-phase dispatch (owner decision resolving the G4 sequencing conflict): new
  `mode` input (`full` | `railway-workers-only`, default `full`; dispatch
  surface now 12 inputs; `deploy-production.ps1` gains `-Mode`). Phase A deploys
  workers only (Vercel lane skipped; evidence finalizer records the expected
  skips and constructs no full-release manifest); the owner then captures
  ADR-082 operator evidence against the current fleet; phase B is the full
  release whose deploy job takes the exact-SHA reuse path, so G4 verifies.
  `railway-workers-deploy` added to the release-evidence manifest failure stages
  in DAG order.
- Provider-contract evidence recorded in
  `docs/workflows/railway-provider-contract-evidence-f132.md` (readback branch
  selected; `deploymentRollback` returns `Boolean!` per live schema — docs drift
  noted). ADR-089 in `DECISIONS.md`; operator route updated in
  `docs/workflows/PRODUCTION_SCRIPTS.md`.

Merge establishes merge eligibility only; production dispatch remains a separate
owner-authorized action under the governing policy. Owner preconditions before
first dispatch: disable autodeploy for both worker services in the Railway UI;
close superseded PR #1411.
