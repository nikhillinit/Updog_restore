## Changes

Release mutation containment remediation for the governed production release
path shipped by F_1.3.2: `deploy-railway-workers.mjs` and its companion release
helpers gain one absolute run deadline and fail-closed deployment-identity
reconciliation.

- One run-level deadline replaces the per-phase budget model: `timeoutMs`
  (default 35 minutes inside the unchanged 45-minute job cap) is computed once
  and threaded through the live-main fence subprocess, every GraphQL request,
  every poll, and recovery. `RECONCILIATION_TIMEOUT` is retired from the
  deploy-reconciliation path in favor of `RECONCILIATION_IDENTITY_UNRESOLVED`.
- Mutation identity is proven by snapshot difference: before each deploy,
  rollback, and redeploy the helper snapshots the bounded deployment-ID set
  (100-page/500-deployment discovery ceiling, exhaustion typed `BLOCKED`); a
  returned ID present in the snapshot is rejected. A lost or ambiguous deploy or
  redeploy response resolves only to exactly one fully verified novel deployment
  ID — never by SHA, ordering, or timestamp.
- An ambiguous rollback accepts exactly one of two proofs — the same intended
  prior deployment transitioning non-ready to fully ready, or exactly one novel
  fully verified prior-commit deployment — and both require the attempted
  deployment read back terminally inactive.
- First-service recovery additionally requires the failed service's attempted
  deployment read back terminally inactive (`assertFailedServiceInactive`):
  missing, transitional, or unknown top-level status blocks recovery; only
  stopped `SUCCESS` or allowlisted terminal-failure status with exact-ID
  inactive instance evidence is accepted.
- Malformed, missing, or repeated pagination state fails before mutation;
  post-mutation reconciliation retains already-observed novel deployment
  handles, and ambiguous reconciliation preserves sanitized causal
  candidate-readback errors.
- Bounded provider and Git operations: the verification poll and the provider
  evidence/recovery-context collectors carry their own absolute deadlines
  (90-second collection default under the two-minute promotion shell timeout;
  two-minute network git-fetch budget under the capture job cap), and
  `validate-target` is pinned to a 15-minute workflow timeout.
- PR #1452's external release binding records the implementation commit, merge
  SHA, reviewed patch, implementation, evidence-report, and reviewed-plan
  digests. PR #1453 corrects the admitted plan/report lineage in
  `docs/3-code-review/CR_w6_v1.3.4.md`; its final documentation head and
  tracked-diff review remain an external pre-merge gate. ADR-089 and operator
  documentation record the runtime contract. WATCH #1 and WATCH #4 remain open
  by accepted decision.
