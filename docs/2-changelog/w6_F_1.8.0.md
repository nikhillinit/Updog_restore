## Changes

### Operating Decisions Spine (F_1.8.0, issue #1289)

Migration `0054_operating_decisions_spine.sql` (additive, replay-safe,
drift-refusing preflights) adds:

- **`operating_decisions`** — fund-scoped decisions with a
  proposed/accepted/rejected/deferred lifecycle enforced by the
  `operating_decisions_enforce_lifecycle` BEFORE UPDATE trigger plus CHECKs:
  immutable core fields, deferred-only follow-up edits (owner and date required
  while deferred), one-shot outcome recording on terminal rows, and same-fund
  single-superseder supersession via composite FK plus partial unique index.
- **`decision_evidence_links`** — decision-sourced evidence links to internal
  analysis references or economics runs (exactly-one-target CHECK, same-fund
  composite FKs, forbid-update trigger reusing
  `internal_economics_forbid_update`).
- **`tasks.idempotency_key` / `tasks.request_hash`** plus the partial unique
  `tasks_fund_idempotency_unique` — task create becomes an idempotent command.

Services and contracts: `decision-service.ts` (idempotent create, xmin-pinned
transition and one-shot outcome, supersede with 409 on proposed sources),
`decision-evidence-link-service.ts`, idempotent `createTask`, and
`decision.contract.ts` with versioned request-hash preimages (actor and
server-controlled status excluded). Task create joins
`isDatabaseBackedIdempotencyRoute` so both serving surfaces share row-stored
key + hash semantics (201 / 200 replay / 409 reuse / 428 missing).

Preflight hardening from code review: named-index preflights refuse unusable
same-named indexes (`indisvalid`/`indisready`/`indislive` false — the failed
`CREATE INDEX CONCURRENTLY` leftover that `IF NOT EXISTS` would keep), and the
`internal_economics_forbid_update` dependency check compares the exact canonical
function body instead of marker text, refusing no-op rewrites.

Tests:
`tests/integration/operating-decisions/operating-decisions-schema.pg.test.ts`
(testcontainers, registered in `tests/config/testcontainers-test-paths.mjs`) —
apply-twice convergence, drift refusal (including the invalid-index and no-op
function-rewrite scenarios), SQL-level lifecycle/immutability/supersession
proofs, cross-fund negative cases, and service idempotency under replay,
conflict, and races; plus unit contract suites for services, routes, and the
idempotency classifier.

Fund-scope posture: no table-level RLS, matching the operating-objects family
(`tasks`, `task_evidence_links`); enforcement is handler/service fund scoping
plus DB-level same-fund composite FKs. Recorded in ADR-091 item 6.
