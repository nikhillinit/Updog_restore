## Changes

### Workspace Context Rail (issue #1288, F_1.9.0 first slice)

Implements the shared fund workspace context and rail on the approved #1284
prototype basis:

- **`FundWorkspaceContext`** ({fundId, vehicleId|null, asOfDate,
  currentPlanVersionId|null, viewPreset}) + `useFundWorkspaceContext`. The
  provider takes the RESOLVED route fund id (null disables all queries) and
  never reads ambient fund state — cross-fund display is unrepresentable.
- **Served-basis provenance only**: `asOfDate` and `currentPlanVersionId` derive
  solely from the dual-forecast response's optional `currentForecastV2` block; a
  present `held` block renders its pinned basis identity plus held disclosure as
  a served golden state. Latest-facts data appears only as freshness metadata
  and vehicle roster (sole `main_fund`, else null-with-reason). Loading, error,
  and settled absence render distinctly at basis, freshness, and identity levels
  — absence wording only after a settled read proves it.
- **`WorkspaceContextRail`** on eight workspace pages: reserved 320px sticky
  column at `xl` (two-column grid), slide-over at 1024-1279px, info-button below
  1024px; solid `#292929` focus treatment; `#2563EB` reserved for Info status;
  presets drive presentation-only section ordering; workspace-nav carries
  `viewPreset` across links plus a disabled Operations placeholder (#1293
  pending).
- **Implementation-slice limitations documented**: uncalled-capital bridge
  panel, recompute action, and evidence navigation ship disabled-with-reason
  (missing authorized bridge read contract; recompute POST lacks idempotency —
  pre-existing defect candidate; no basis-correlated evidence read). No new
  backend routes or contracts (#1290 owns those). No sticky as-of.
- Client financial-facts ingress uses a type-derived string-or-structured
  participation-term union covering all five persisted policy versions, pinned
  by a contract-parity suite (avoids the Node-only shared-contract bundle leak).
