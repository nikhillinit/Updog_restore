## Changes

### V2 F2 Completion (F_2.0.2)

Completes the narrow F2 success surface before F3 introduces event
transitions. Computation-only; no routes, persistence, queues, flags, UI,
schema, or production action.

- **Opening state admitted**: the F2 envelope now accepts a zero-event,
  deal-by-deal input carrying deal-by-deal opening investment provenance
  (investment slices and entitlement pools). The admission envelope widened by
  exactly two predicates; every other F2-entry refusal boundary is unchanged.
- **Deep-sealed normalized input**: the normalizer recursively freezes the
  complete normalized object graph after computing the unchanged canonical
  `normalizedInputHash`.
- **Runtime opening types + balance-forward journal**: hydration builds
  explicit opening cash-lot, investment-slice, and entitlement-pool runtime
  types plus a closed three-account journal (`cash`, `invested_basis`,
  `opening_unreturned_capital`) beside the untouched event-lane state. Opening
  positions are never period cash flows and never enter IRR/XIRR or cash-flow
  vectors.
- **Closed receipt 2.1.0**: single required field set with closed
  five-component manifest, required `sourceRefs`/`upstreamReceiptIds`, full
  15-field partner and class ledgers, opening-position disclosures, journal
  rows, one typed result-hash preimage (the receipt without `resultHash`), and
  prospective output-row (100,000) plus final serialized-output-byte (16 MiB)
  limits.
- **Truth evidence**: V2-S-0100 lands as a frozen literal input + expected
  receipt fixture (resultHash
  `ea74f8d284ba0625568f89e9b3ffe1dad32abb9d37bb0c0b05bdc2735a48916f`); V2-S-0101
  regenerated under 2.1.0 with a consumed changed-case manifest preserving its
  frozen 2.0.0 hash
  (`e0263b99740005feffcb89bb000d931b00b9232b6086b13056849a191eb07e28` ->
  `36b5c917107abc2326ec7cc7048d8835e34cf4258705297740618824fe261331`, input
  hash unchanged).
- **Governance**: ADR-087 (successor to ADR-085) records the receipt 2.1.0
  field set, opening-position versus cash-flow separation, journal accounts,
  hash preimage and manifest, the literal fixture, and the F2/F3 boundary.
  `processEvents` semantics, event-stream atomicity, and `sourceCashLotId`
  lineage move to F3.
