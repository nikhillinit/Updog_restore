## Changes

### V2 Conformance Closure (F_2.0.7, batches A1-A7)

Closes the four conformance gaps verified against the F_2.0.0 normative text
(`docs/1-plans/F_2.0.0_v2-core-financial-model.plan.md:280-337`):

- **A1/A2 — missing-first refusal precedence.** A proposed ADR-090 amendment
  (owner ratification at merge) fixes the fund-expense allocation validation
  order: existence of every referenced cash-source lot first (canonical
  refusal over the sorted, deduplicated set of all missing lot ids —
  `CASH_SOURCE_ALLOCATION_VIOLATION` at `provenance`), then event-origin
  contribution-settlement eligibility (`SCHEMA_VALIDATION_FAILED`), then
  amount/balance/total validation. The winning refusal object is independent
  of allocation order; the prior mixed missing+ineligible ambiguity (noted as
  uncovered in `w6_v2.0.6.md`) is closed.
- **A3 — positive caller-event magnitudes.** `V2Event.amountUsd` now uses an
  additive `PositiveMoneyDecimalStringSchema` (zero and signed values refuse
  `SCHEMA_VALIDATION_FAILED` at `normalization` for all nine caller kinds);
  the shared `MoneyDecimalStringSchema` and engine-derived directional rows
  are unchanged.
- **A4 — conditional `other` description.** Validation-only `superRefine`:
  `expenseCategory: "other"` requires a trimmed non-empty `description`;
  the four named categories keep it optional. No trim transform — parsed
  bytes and `normalizedInputHash` are byte-identical for conformant inputs
  (asserted by test).
- **A5 — receipt category grouping.** New fund-level
  `expenseTotalsByCategory` (five keys always, six-decimal strings, zero
  fill) derived from staged fund-expense effect records that now carry
  `expenseCategory` provenance; conserved three ways (journal
  `fund_expenses`, total partner `cumulativeExpenses`, admitted event total)
  and included in the closed receipt shape and canonical preimage.
- **A6 — complete atomicity certification.** The equality-snapshot helper now
  covers every `EventStreamState` field via exhaustive per-key construction
  (compile-time error on new uncovered fields), including
  `cumulativeExpenses`, `consumptionRecords`, discriminated
  `eventEffectRecords`, `partnerEffectRecords`, and lot `sourceKind`
  discriminators.
- **A7 — version and hash transition.** Receipt contract
  `internal-economics-receipt/2.3.0`; composite, event-engine, and
  receipt-serializer identities 2.3.0. Accepted input `2.0.1`, normalizer
  `2.0.1`, both waterfall contracts `2.2.0`, and `package.json` `1.6.0`
  unchanged. Changed-case manifest v1 is frozen as historical 2.2.0
  certification; new manifest v2 certifies the 2.2.0 -> 2.3.0 transition
  (before hashes chain to v1's after hashes; one recorded reason per changed
  hash; live derivation asserted both directions).

Excluded (tracked separately): per-security proceeds routing defect (issue
#1458), 2B correction/write-off/conversion semantics, 2C persistence/queues,
#1373 gate redesign. No routes, migrations, workers, flags, or client code.
