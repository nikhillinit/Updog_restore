## Changes

### V2 Catch-Up Allocation Parity (F_2.0.4)

Unifies the duplicated GP catch-up arithmetic in both V2 waterfall engines
behind one pure Decimal leaf and closes the split-conservation gap.
Engine-internal implementation-conformance correction only: the catch-up tier
remains unreachable on the public derivation path (admission guard accepts only
a single carry-only tier with zero events), so public-path behavior is
byte-identical — frozen V2-S-0100/0101 hashes and the 4206-byte receipt pin are
unchanged.

- **Locked methodology**: new leaf
  `shared/lib/internal-economics/v2/catch-up-allocation-v2.ts` implements the
  ratified F_2.0.0 stopping rule `grossCatchUpDue = max(0, (c(G+L)-G)/(g-c))`,
  replacing the divergent `(c(openingPrefPaid+remaining)-G)/g` both engines
  executed (wrong denominator, opening-scalar profit base, folded-in
  undistributed proceeds).
- **Joint quantized split**: each catch-up and carry tier allocation is
  converted to six-decimal integer units exactly once and split GP/LP with a
  single largest-remainder pass (GP favored on equal remainders); engines
  consume the total reconstructed from integer units, so emitted buckets can
  never over-distribute relative to what was subtracted.
- **Binding-cap clamp** (found in Codex review round 1): HALF_UP quantization of
  an allocation that binds at available proceeds could exceed them by half a
  unit; `decimalToCentsFloor` caps quantized units at floored availability in
  `splitQuantizedGpLp`, supplied by the catch-up leaf and both carry call sites.
- **Cumulative profit accumulators**: whole-fund keeps one fund-level G/L
  accumulator (seeded from opening scalars, `excluded`-treatment resume rule;
  nonzero-opening `pari_passu` resume defensively refused pending GP/LP
  preferred provenance); deal-by-deal keeps one clean-opening accumulator per
  entitlement pool, replacing per-pool re-grants from unchanged fund-level
  opening scalars. Later tiers now see profit granted by earlier tiers in the
  same run.
- **Defensive invariants**: a positive catch-up or carry GP/LP bucket with an
  empty eligible partner cohort throws an internal error instead of silently
  dropping the bucket; deal-by-deal throws on nonzero scalar opening profit
  history when a catch-up tier is present (cannot be allocated across pools).
- **Coverage**: 20 new tests — leaf oracle and conservation suite (including a
  current-vs-locked distinguishing fixture), whole-fund and deal-by-deal
  catch-up arithmetic (first-ever), distinct-deal pool independence and order
  invariance with executable pool-key preconditions, single-pool cross-engine
  parity, empty-cohort and opening-history defensive cases.

## PR #1433 review follow-up

Post-review corrections on the release branch (PR review round, Codex-verified):

- **Preferred-return double-pay fail-closed (P2)**: deal-by-deal read the
  fund-level `accruedPreference` ledger fresh in every entitlement pool without
  consuming it, so multi-pool runs re-paid the same balance per pool and fed the
  re-paid amounts into per-pool catch-up basis (pre-existing defect; publicly
  dormant behind the carry-only admission envelope). Because the ledger carries
  no per-pool provenance, and serial cross-pool consumption makes aggregate
  catch-up/carry order-dependent (Codex counterexample: identical sufficient
  proceeds, GP profit 40 vs 60 by pool order), multi-pool runs with a positive
  preference entitlement now fail closed with an internal error — the same
  pattern as the opening-history guard. Single-pool runs remain valid.
- **Preferred-return quantization**: both engines emitted quantized per-partner
  preference amounts while reporting (and subtracting) the raw Decimal target.
  Both now quantize once in integer units — floored partner balances bound the
  ledger claim, floored availability bounds proceeds — and reconstruct the
  allocated total from the emitted units (same discipline as catch-up/carry).
- **Tests**: pool order-invariance is now asserted with zero preference (the
  seeded variant fails closed by design); new multi-pool refusal regression and
  a single-pool conservation regression whose preference weights deliberately
  differ from settled-capital weights. Suite: 322 internal-economics-v2 tests.
- **Hygiene**: stale
  `canonical-receipt-changed-case-manifest-v1.user-placeholder.bak` deleted; the
  historical `.mimosa` gitleaks allowlist is pinned to commit `c20bbbd69` and
  the content-addressed blob path shape (later force-adds are not suppressed);
  `.gitignore` covers `.mimosa`/`.zcode` as bare entries too so a future symlink
  bridge stays ignored. Dockerfile CVE patch kept as targeted `apk upgrade`: no
  patched `node:22.23.2-alpine` digest exists yet and exact version pins break
  when Alpine rotates packages.
