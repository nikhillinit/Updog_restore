## Changes

Implements F_1.2.4 Phase 2 (WS2 "Repair & Prove", gate G3) plus the Phase 1
artifacts (audit + ADR-073). Fixes the class of production failures where every
`database.transaction(...)` call reachable from the Vercel surface threw at
runtime (neon-http driver has no transaction support).

- **Surface-scoped driver switch (ADR-073 G2-2)**: `server/db.ts` Vercel branch
  moves from neon-http to the Neon WebSocket `Pool` +
  `drizzle-orm/neon-serverless` (transaction-capable). Fixed a latent bug in
  BOTH Neon branches: `neonConfig.webSocketConstructor` must be `ws.default`,
  not the module namespace (namespace made every non-localhost WebSocket fail
  with "fetch failed" - probe-verified against the prod pooler). Pool error
  listeners added (idle WebSocket failures no longer crash the process).
- **P0 claim-last CTE rewrites**: mode update
  (`fund-calculation-mode-service.ts`), activation latch
  (`current-forecast-reference-service.ts`), and the audit row-43 mirror
  (`fund-moic-input-service.ts`) each collapse to ONE guarded data-modifying CTE
  statement: FOR UPDATE guard -> version/latch-fenced mutation (with same-key
  NOT EXISTS fence) -> ledger row inserted LAST already 'completed'. A fresh
  idempotency row can never exist in 'pending' state; guard failure writes
  nothing. The plan's claim-atomicity invariant was amended to claim-last:
  PostgreSQL WITH sub-statements share one snapshot, so a CTE can never complete
  a row another CTE inserted in the same statement (empirically proven).
- **Pointer advance escalated to class (b)** per the plan's pre-authorized
  clause: the guard-fenced CTE cannot deliver the serial-order-equivalent
  both-succeed contract under READ COMMITTED (the losing statement's supersede
  filters the new head on a pre-commit snapshot; lock-wait re-evaluation cannot
  rescue it - proven by the lane's concurrency test). Keeps its callback
  transaction; correct on Vercel via the driver switch.
- **LP-reporting repairs**: metric-run approve/lock, evidence create, and
  narrative edit/review/approve rewritten as guarded single-statement CTEs (CAS
  in-statement, error codes preserved via discriminating guard columns;
  narrative CTE carries an explicit lock-order fence matching report-package
  assembly). The five duplicated broken `withTransaction` helpers deleted; the
  two genuinely multi-statement paths (report-package, planning-fmv) use one
  shared `runInTransaction`; dead `skipTransaction` escape hatch retired.
  planning-fmv catch hardened: unexpected errors now mark the idempotency row
  'failed' instead of stranding it 'pending' forever (already-stranded prod rows
  deferred to a follow-up data repair - user decision 2026-08-07).
- **transaction-support hardening + guardrail**: near-match driver errors now
  fail loudly ("error changed shape; update pin") instead of silently
  rethrowing; new `guard:transaction-support:check` lint guardrail enforces
  ADR-073 allowlists for `runWithTransactionFallback`/`runInTransaction` and
  forbids new local `withTransaction` helpers under `server/services/`.
- **Real-Neon test lane** (`tests/integration/neon-http/`,
  `vitest.config.neon.ts`, `npm run test:neon`): testcontainers-managed
  local-neon-http-proxy + wsproxy + postgres:16 exercising BOTH drivers
  explicitly (never via `server/db.ts`). 25 tests: driver-semantics pins,
  post-repair proofs (success/replay/guard-fail per path contract), and 5
  concurrent-writer contract tests. Wired into CI as a fail-closed member of the
  `CI Gate Status` rollup (`neon-lane` job + `neon_lane` path filter).
- **pg-driver proof**: `current-forecast-reference.pg.test.ts` extended with the
  full mode->activate->pointer lifecycle on real migrated Postgres, so every
  rewrite is proven on both drivers.
- **Docs**: `docs/audits/F_1.2.4-transaction-reachability-audit.md` (68 rows,
  30a/28b/10c, G2 ratification record) and ADR-073 land with this release. Note:
  G2-4 ratified all 30 class-(a) rows for rewrite; this release lands the P0 +
  LP subset required by G3 - the remaining (a) rows are functionally correct via
  the driver switch and stay available for later round-trip-efficiency rewrites.
