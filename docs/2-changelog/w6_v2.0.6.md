## Changes

### V2 Expense Lot Eligibility + Partner Expense Attribution (F3b hotfix)

Post-merge review of v2.0.5 confirmed two violations of the F_2.0.0 normative
rules (plan lines 331-337) in `main`:

- **Eligibility (was: any registry lot accepted).** `processFundExpense` now
  refuses `SCHEMA_VALIDATION_FAILED`/provenance when any cash-source allocation
  references a lot that is not an event-origin contribution-settlement lot.
  Opening-cash and realization-proceeds lots can no longer fund expenses (the
  proceeds half predates F3b; F3b's opening-lot seeding widened it).
- **Attribution (was: `cumulativeExpenses` hardcoded to zero).** Fund expenses
  attribute per partner by contribution-lot ownership at exact allocation
  amounts: `PartnerLedgerState` gains staged `cumulativeExpenses` (cloned,
  partner-effect-recorded), receipt partner and class ledgers project the staged
  value, and conservation now requires receipt-equals-staged plus journal
  `fund_expenses` total equal to the sum of partner expenses.

Implementation identities bump to 2.2.1 (event engine, composite implementation,
receipt serializer) because expense-bearing streams change refusal semantics and
receipt values; receipt contract and both waterfall versions stay 2.2.0 (field
shape and waterfall behavior unchanged). Changed-case manifest afterResultHash
values regenerated for V2-S-0100 and V2-S-0101 under the 2.2.1 identities;
frozen before-hashes and normalizedInputHash values untouched. Test type
hygiene: invalid `readonly Array<T>` annotations replaced with
`ReadonlyArray<T>`.

Declined from the same review (recorded rationale): rewriting the committed
CR_w6_v2.0.5 line citations (accurate at review time; shifted by the commit's
prettier pass) and adding frontmatter to release docs (no `docs/2-changelog/` or
`docs/3-code-review/` document carries frontmatter; tracked by the staleness
report).

Refusal-precedence follow-up (same release, second review round): the
eligibility check now runs before generic amount/balance validation, so an
overdrawn ineligible lot refuses `SCHEMA_VALIDATION_FAILED` rather than
`CASH_SOURCE_ALLOCATION_VIOLATION`; unknown lots still take the generic
existence refusal. Overdrawn opening-lot and proceeds-lot regressions added.

only; production dispatch remains a separate owner-authorized action under the
governing policy.
